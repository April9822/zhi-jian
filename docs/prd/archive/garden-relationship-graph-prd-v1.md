**用户已拍板的方向：** 「**重构为关系图语义**」——保留中式田园画风，让四个元素之间**有可见的连接线/光带**，养分增长时连接线**变亮变粗**，用户能直接「看见关系」。

## 2. 产品目标

**一句话目标（可验证）：**
> 用户打开花园页后，能在 3 秒内指出「自我」与「家人/伴侣/朋友」之间**至少一条发光连接带**，并能说出这条带的亮/粗变化代表这段关系的养分状态。

**验证方式（验收时执行）：**
1. 截图花园页 → 画面中存在 ≥1 条可见的、连接两个角色的连接带（非装饰纹理）。
2. 养分从 0 增至 100 → 连接带线宽/亮度发生可见阶跃变化（三档）。
3. 不含任何维度分数、禁止词、人格/道德/侮辱性表述。

**三个正交子目标：**
- G1 **可见关系**：把「四株孤立植物」重构为「一张有中心、有连线的关系图」。
- G2 **可见生长**：让「关系养分」数字与花园画面产生直接视觉联动（数字 → 连线变化）。
- G3 **视觉收口**：消除 emoji/CSS 混用、锚点重叠、树冠越界、高度挤压等工程缺陷。

## 4. 关系图语义定义（本次核心）

### 4.1 关系图「画什么」

**核心变化：从「并列展示四个角色」改为「以自我为根的关系星图」。**

- **中心节点 = 自我（新芽）**：位于场景中下部偏左的视觉重心，作为整个关系图的**根节点**。所有连接带都从这里出发。
- **外围节点 = 家人（古树）/ 伴侣（花丛）/ 朋友（小动物）**：环绕排列成**松散圆弧**（中式山水构图，不追求机械对称）。
- **连接带 = 关系**：从「自我」到每个已存在角色，画**一条概念化的光带**（见 4.4 实现方式）。**光带本身才是主角**——它表达「你们之间有关系、关系有强弱」。

> 一句话：**原来的画面主体是四株植物，新画面主体是三束「自我 ↔ 他人」的光。**

### 4.2 连接带承载什么信息（守住宪法）

连接带**只承载「强弱 / 变化 / 趋势」的定性感知，绝不给出百分比分数**。

| 可表达 | 不可表达（违反宪法/术语纪律） |
|---|---|
| 「这条连接更亮/更暗」 | ❌ 「理解度 75%」 |
| 「这条带比上次更粗」 | ❌ 「关系分数 82」 |
| 「连接带上有流动光点 = 近期有互动」 | ❌ 「互动频率 3.2 次/周」 |
| 「这里有一条淡淡的、将连未连的丝线」 | ❌ 「修复度 40%」 |

**每条连接带的三项定性属性（内部数据结构，不外显为数字）：**
1. **强度（strength）**：0–100 的内部值 → 只映射为线宽三档（细/中/粗），**页面不显示数字**。
2. **活跃（active）**：布尔 → 是否出现「流动光点」（近期有互动/有倾诉记录）。
3. **趋势（trend）**：`up | steady | down` → 决定连接带端点是否有一个极轻的「呼吸上浮 / 静止 / 沉降」动效差异（不写文字、不显数字）。

> ⚠️ 所有对外文案必须遵守：不使用「关系能量 / 关系分数 / 数据看板」；统一用「关系养分 / 关系花园 / 情境回顾 / 成长建议」。

### 4.3 养分增长 → 连接带变化规则（精确到数值）

**养分来源：** `#nurture-total`（现有 `getNurture()`，localStorage key `zhijian-nurture`），0 起，无上限。

**连接带状态由「全局养分总量」分三档驱动（0–33 / 34–66 / 67+）**，每个档位同时改**线宽**与**透明度/发光**：

| 档位 | 养分区间 | 连接带线宽 | 主色 & 透明度 | 附加效果 | 语义文案（可放 `.glabel` 或状态文案） |
|---|---|---|---|---|---|
| **薄 | 0–33** | `1.5px` | `rgba(213,168,90,0.28)` | 无光点；静态 | 「连接刚刚开始」 |
| **中 | 34–66** | `3px` | `rgba(213,168,90,0.55)` | 静态微光（外发光 blur 2px） | 「连接在生长」 |
| **厚 | 67–100** | `5px` | `rgba(213,168,90,0.85)` | 沿线**流动光点**（3s 一循环，匀速） | 「连接很活跃」 |
| **满 | ≥100** | `5px` | 同「厚」+ 端点 4s 呼吸光晕 | 流动光点 + 端点光晕 | 「连接正繁盛」 |

**分档切换动效：** 用 `transition: stroke-width .8s cubic-bezier(.4,0,.2,1), opacity .8s ...`（对应设计系统「颜色过渡 800–1200ms」），**不瞬切**，让用户看到「它变粗了」的过程。

**养分获取增量的反馈（回归现有交互）：**
- 完成一次「情境回顾」（报告页生成成功）→ `addNurture(+10)`。
- 花园内点击任一角色 / 选择小动物 → `addNurture(+1)`（保持现有浇灌反馈 `waterCreature`）。
- 每次养分变化后调用 `updateRelationshipBands()`，按新档位更新所有连接带的 class（如 `band--thin / band--mid / band--thick`）。

> **实现建议（给工程师）：** 连接带用**内联 SVG `<path>`**（`<svg class="relation-graph" viewBox="0 0 100 100" preserveAspectRatio="none">`），`stroke-width` 用 `vector-effect="non-scaling-stroke"` 防拉伸变形；流动光点用 `stroke-dasharray` + `stroke-dashoffset` 动画（纯 CSS `@keyframes`，无 JS 库）。若团队更倾向 Canvas，则复用 `#gardenCanvas` 增加一条「连接带图层」，但**优先 SVG**（易做 hover、易做 CSS 过渡、易做无障碍）。

### 4.4 单一元素 / 部分元素缺失时的处理

角色存在性由**用户实际记录的关系**决定（V1 可用 localStorage `zhijian-relations` 存已出现的角色 id 列表；无记录时给默认全集）。

| 场景 | 处理规则 |
|---|---|
| **只有一个角色**（如只有「自我」） | **不画任何连接带**，自我节点居中，其余位置留白 + 一株远处的墨色小丘；页面文案：「先记录一段对话，让关系显现」。**绝不臆造**不存在的人。 |
| **两个角色** | 画 1 条带（自我 ↔ 该角色），构图偏左，右侧留白留境。 |
| **三个角色** | 画 2 条带，圆弧排列。 |
| **四个角色（全集）** | 画 3 条带（家人/伴侣/朋友各一条连向自我）。 |
| **角色新增**（首次出现某类关系） | 该连接带以「**淡入 + 由细到当前档位变粗**」入场（600ms），并有一次轻微的高亮脉冲。 |
| **角色隐藏**（长期无该关系记录） | 连接带降到「薄」档并**降低不透明度至 0.15**，保留极淡的「将连未连」感，**不删除**（不否定用户曾有的关系）。 |

> **朋友角色特殊说明：** 朋友由「小动物选择」确定（狐狸/兔子/松鼠/小鹿），连接带连向所选动物。未选择动物时，朋友节点不出现（不画带），`animal-hint` 提示「选一位小伙伴吧」保持不变。

### 4.5 关系快照 / 四季表达（复用已有 `SEASONS` 常量）

**结论：需要，但作为「氛围层」，不作为「时间轴图表」。**

复用 `SEASONS = ['冬·沉淀季','春·生长季','夏·繁盛季','秋·收获季']`，把季节映射为**连接带与场景的整体氛围参数**（不新增页面、不新增图表组件）：

| 季节 | 索引 | 连接带氛围 | 场景调整 | 状态文案（`.nurture-status`） |
|---|---|---|---|---|
| 冬 · 沉淀季 | 0 | 带到主色偏 `#8EA5B5` 雾蓝，缓慢呼吸 | 光更淡、光斑少 | 「关系在安静地沉淀」 |
| 春 · 生长季 | 1 | 带到主色 `#D5A85A`（默认） | 现有春景 | 「你的关系正在慢慢生长」 |
| 夏 · 繁盛季 | 2 | 带偏暖橙、光点更快（2s） | 阳光更亮 | 「关系正值繁盛」 |
| 秋 · 收获季 | 3 | 带偏金 `#E8C060`、偶尔飘叶 | 少量落叶粒子 | 「你收获了一些理解」 |

**季节推进规则（沿用现有逻辑，微调）：** 当**所有存在角色**的成长阶段均 ≥ 当前季节索引 +1 时，季节前进一档（最多到「秋」）。**无角色时不推进**。

> 季节**永不显示为数字或进度条**，只通过色温 + 文案 + 动效体现。

## 6. UI 结构描述（分层布局方案）

### 6.1 目标分层（自下而上，z-index 递增）

| 层 | 定位方案 | 内容 | 变化说明 |
|---|---|---|---|
| **L0 场景底** `.garden-bg` | `top:0; height:58%` | 天空渐变 + 太阳 + 两座墨山 + 远景树影 | 高度从 65% 降到 **58%**，为树冠腾出天空呼吸位；太阳改 `top:6% right:26%` 并**缩小至 60px** |
| **L1 关系星图** `.relation-graph`(SVG) | `position:absolute; inset:0; width/height:100%` | **新增**：连接带路径（自我→家人/伴侣/朋友） | z-index 2；`pointer-events:none`（由下层节点承担 hover） |
| **L2 中景** `.garden-midlayer` | `bottom:30%; height:46%` | 古树（家人） | `.tree-crowns{top:-58px}`（原 -75px），保证树冠顶不越出容器 |
| **L3 近景** `.garden-fore` | `bottom:12%; height:40%` | 花丛（伴侣）、小动物区（朋友）、幼苗（自我） | 见 6.3 锚点重排 |
| **L4 地面** `.garden-floor` | `bottom:0; height:12%` | 地面弧形 | 不变 |
| **L5 粒子** `#gardenCanvas` | `inset:0` | 光斑动画 | 不变；若采用 Canvas 方案，连接带可并入此层（二选一，优先 SVG 独立层） |

### 6.2 关系星图锚点（关键坐标，供 SVG 绘制）

SVG 使用 `viewBox="0 0 100 100"` + `preserveAspectRatio="none"`，锚点以百分比定位（工程师按实际 DOM `getBoundingClientRect()` 换算，天然响应式）：

| 角色 | 锚点（相对 garden-scene 的近似 %） | 说明 |
|---|---|---|
| 自我（新芽） | `x≈20%, y≈68%` | 星图根节点，左下方 |
| 家人（古树） | `x≈24%, y≈30%` | 中偏左，树干中部 |
| 伴侣（花丛） | `x≈52%, y≈62%` | 中偏下，花头位置 |
| 朋友（动物） | `x≈74%, y≈66%` | 右下，所选动物位置 |

连接带用**二次贝塞尔曲线**（`Q`）轻微下垂/上扬，营造「垂柳/山径」中式感，避免机械直线。

### 6.3 近景锚点重排（解决 P0-7 重叠）

当前问题：花丛 `left:38%`、动物区 `left:50%`（宽约 260px → 覆盖 37%~63%）、幼苗 `left:12%`，三者底部锚点相互压叠。

**新方案（无重叠）：**
- **自我 · 新芽**：`left:8%; bottom:6%`（左端）
- **伴侣 · 花丛**：`left:46%; bottom:14%`（中，**上抬**避开动物区）
- **朋友 · 小动物区**：`left:72%`（**放弃 translateX(-50%) 居中**，改为右对齐 `right:4%`），`bottom:4%`；宽度收缩为最多 4 个 sprite 横排（窄屏改为 **2×2 网格**，`flex-wrap:wrap`，宽度 ≤ 200px）
- 三者最小水平间距 ≥ 24px；480px 媒体查询下动物区改网格排列，确保 320px 不溢出。

### 6.4 养分卡与联动的空间关系

`.nurture-card` 保持顶部卡片位置不变，但：
- `#nurture-total` 数字保持不变（这是**关系养分的总量，非维度分数**，符合宪法）。
- `#nurture-status` 文案改由「档位 × 季节」表驱动（见 P1-5），如「连接在生长 · 你的关系正在慢慢生长」。
- 卡片与星图之间加一条**极淡的下引光晕**（可选 P2），暗示「养分流进花园」，强化数字↔画面的因果感。

### 9.2 判定依据优先级链（无显式选择时的推断顺序）

系统按下列顺序**逐级短路**，命中即止：

| 优先级 | 依据 | 来源 | 命中条件 |
|:--:|---|---|---|
| **P1** | 用户显式选择 | 花园/输入页选择器 `zhijian-scene`（若已提供） | 用户明确选了「这段对话是关于…」 |
| **P2** | AI 结构化信号 | `analysis.parties[].relation` 或 `analysis.scene`（若 API 已返回结构化关系字段） | 字段存在且非空 |
| **P3** | AI 输出文本关键词 | `analysis.parties[].label / nickname` + `analysis.coreInsight.*` 文本，经**称呼词词典**匹配（见 9.1 线索列） | 命中唯一场景类型 |
| **P4** | 用户粘贴文本关键词 | 原始 `conversation` 前 3 行说话人标签 + 称呼词 | 命中唯一场景类型 |
| **P5** | 兜底 | 以上均未唯一命中 | → `none`（执行 9.3） |

**冲突消解（P3/P4 命中多个角色时）：** 按「词典命中次数最多者优先；次数相同则按 伴侣 > 家人 > 朋友 的亲近度排序」取**唯一主轴**（详见 9.4）。

**⚠️ V2 修订 · 冲突消解扩展为 6 节点，并新增「截胡防线」（见 §9.9）。**

**（a）亲近度排序扩展为 6 节点全序：**

`partner > child > family > colleague > friend > none`

> 排序依据（按「对话直接参与方的亲密与责任强度」）：伴侣与子女是**同一生活单元内、责任最重**的关系；父母/兄弟姐妹次之（有血缘但常非共同生活）；同事是**高频共处但边界清晰**的关系；朋友是**低频但自愿**的关系；`none` 最后。
> 这与 §9.4「直接参与方优先」原则一致——不是按亲密度打分，而是按**「这段话里，谁是在场的那个人」**排序。

**（b）截胡防线（防止 `family` 关键词抢走 `child` / `colleague` 的主轴）：**

| 编号 | 规则 | 说明 |
|:--:|---|---|
| **G1** | **限定词优先于泛指词** | `child` 词典（孩子/儿子/女儿/宝宝/上学/作业）与 `family` 词典（妈/爸/婆婆/公公/家里）同时命中时，**先判「这段话的直接参与方是谁」**：若参与方是子女（如「辅导作业时和儿子吵了」），主轴 = `child`，即使句中出现「妈」也只作**背景提及**计数，**不参与主轴竞争** |
| **G2** | **`colleague` 专属词短路（须带前置条件）** | 命中 `colleague` **专属词**（领导/老板/同事/项目/开会/绩效/客户/加班/汇报）**且**「直接参与方是职场关系」时，**直接短路到 `colleague`**，不再进入与其他节点的次数比较。⚠️ **缺一不可**——只看词不看参与方会误吞「我老婆嫌我加班多」（详见下方 G2 修正版 + §9.9 H3/H4） |
| **G3** | **`family` 与 `child` 的判定顺序固定** | 先判 `child`（检查是否有子代参与方线索），**再**判 `family`。顺序固定、不得颠倒——这是「规则顺序导致截胡」的唯一根治方式 |
| **G4** | **`none` 只在 P5 兜底产生，不得被 P3/P4 直接命中** | P3/P4 阶段**禁止**把未唯一命中的结果直接写成 `none`（原表述有歧义）；必须走完 P1→P4 全部路径且**确认无任何节点命中**，才落 `none` |

> **不再使用「次数最多者优先」作为主判据的场合：** 当命中词分属 `family` 与 `child` 时，**次数不参与竞争**，一律由 G3 的顺序 + G1 的「直接参与方」决定。次数的意义仅用于**同节点内部的置信度**，不用于跨节点抢主轴。

**关键约束（宪法）：** 关键词词典**只收录中性称呼词**。禁止收录「妈宝 / 扶弟魔 / 凤凰男 / 原生家庭 / 创伤 / 控制狂」等诊断性、审判性、侮辱性词汇；若用户原文出现此类词，**只做文本匹配计数、绝不回显、绝不进入任何 UI 文案**。

### 9.3 兜底规则（`none` 情况）——**最终结论：采纳你的倾向，并加一条约束**

**结论：判定不出目标节点时，不加给任何关系节点；但在花园里留下一次「无名记录」，且该记录不进入任何节点养分。**

**⚠️ V2 修订：`none` 的覆盖范围收窄。原「职场 / 陌生人 / 无法判断」三类中，职场已移出 → `colleague`。**

| 判定失败原因 | 花园表现 | 养分归属 | 文案（定性、无分数） |
|---|---|---|---|
| `none`（**仅限：陌生人 / 服务人员 / 无法判断 / 混合**） | 场景中飘落 **1 片落叶（`garden-leaf`）**，或以 **一枝无名小花（`nameless-bloom`）** 点缀 | 只增 `zhijian-nurture` 总量，**不增任一 relationship 节点** | 「这次对话，你也在认真看见自己」 |

> **V2 起 `none` 的准入条件（必须是「本就不存在长期关系」）：** 与陌生人 / 客服 / 快递 / 司机 / 网友 / 路人；或**线索不足无法判断**；或**多类关系混合且无直接参与方**。
> **`colleague` 不再是 `none`**：职场是**存在的关系**，有专属生态区域（同事 · 林间营地），养分必须落到 `colleague` 节点。
> 判定 `none` 前必须确认：**G1–G4 四条截胡防线已全部走完**（见 §9.2），避免「本该进 `child` / `colleague` 的对话被兜底吞掉」。

**为什么这样定（评估结论）：**
- 强行塞进 `family/partner/friend` 会造成**语义污染**——把职场冲突记成「家人关系生长」，用户会不信任花园。
- 但**完全丢弃**会让用户觉得「白分析一场」，破坏「每次理解都是水」的核心隐喻。
- 因此折中：**留下无归属的「无名记忆」**，既诚实（不臆造关系）又有温度（不至于空手而归）。
  **V2 补充：这条折中仅适用于「真的没有长期关系」的情形；职场与子女都已有各自节点，不属于此列。**
- **追加约束：** 落叶/无名花**上限 5 个**，超出后不再叠加（避免花园被无归属装饰淹没）；且**永不**连出根脉（`none` 不生成 band / root-vein）。

### 9.4 多目标情况处理——**最终结论：只给「主轴」，不给副轴，按 100/0 而非按比例**

**规则：一次分析只认定一个「主轴关系」，全部养分（100%）加给主轴的唯一节点；不拆分、不按比例分配。**

**⚠️ V2 修订：下表扩展为 6 节点，并明确「直接参与方优先」为**唯一**裁决原则。**

| 情形 | 处理 |
|---|---|
| 一次对话同时涉及「家人」和「伴侣」（如夫妻讨论与公婆的关系） | 主轴 = **伴侣**（`partner`）。理由：对话的**直接参与方**是伴侣，冲突发生在两人之间；与父母的关系是**背景议题**，不构成星图节点。 |
| 同时涉及「伴侣」和「朋友」 | 主轴 = **伴侣**（直接参与方优先）。 |
| 同时涉及「家人」和「朋友」 | 主轴 = **家人**（`family`）。 |
| **同时涉及「子女」和「伴侣」**（如夫妻争论怎么管孩子） | 主轴 = **伴侣**（`partner`）。理由：**同辈的直接参与方是伴侣**；孩子是**议题**。**例外**：若对话直接发生在一方与孩子之间（如「我和儿子吵架了」），主轴 = **`child`**。 |
| **同时涉及「子女」和「父母」**（如「我妈总干涉我怎么管孩子」） | 主轴 = **`family`**。理由：**直接参与方是「我妈」**——说话人与母亲之间在冲突；孩子是**被干涉的议题**，不是在场的那一方。**这是 `family` 与 `child` 最易混淆的一格，按「谁在场」而非「谁被提到」判定。** |
| **同时涉及「同事」和「朋友」**（如「我和同事以前是朋友」） | 主轴 = **`colleague`**（G2 强命中断路优先）。 |
| **同时涉及「同事」和家人/伴侣**（如「我老婆嫌我加班太多」） | 主轴 = **伴侣**（`partner`）。理由：**直接参与方是伴侣**；「加班」只是话题。**注意：此处不得因命中「加班」就短路到 `colleague`——G2 短路仅在「对话发生在职场关系之间」时生效**（见下方 G2 修正）。 |
| 多人对话（3–5 方）且跨角色 | 取**参与人数最多的那一类关系**为主轴；并列时按 6 节点全序 `partner > child > family > colleague > friend > none`。 |

**⚠️ G2 修正（重要，防止 `colleague` 误吞）：**
原表述「命中 `colleague` 专属词即短路」会在「我老婆嫌我加班多」这类句子上**误吞主轴给 `colleague`**。修正为：

> **G2（修正版）**：仅当 `colleague` 专属词命中的**同时**，判定「**对话的直接参与方是职场关系**」（说话人标签/参与方线索指向同事、领导、下属、客户等），才短路到 `colleague`。**若专属词只是出现在话题里（如「我老婆」「我妈」明确在场），专题词不参与短路。**

**判定依据（为什么是主轴而非比例）：**
- 「按比例 50/50」会让星图出现**半亮的带**，用户无法理解其含义，也**极易被误读成分数**（违反宪法与术语纪律）。
- 主轴规则与「星形拓扑」（Q1 已定）一致：自我是原点，一次对话只在**一段关系**上留下痕迹，语义清晰。
- 副轴信息不丢失：它仍体现在报告页的「情境回顾」里，只是**不写进关系花园的养分账本**。

### 9.5 `zhijian-relations` 数据写入契约

**谁写（产品语义契约，2026 定稿）：**
- **唯一写入函数**：`applyAnalysisToGarden(analysis, opts)`。**只有它**能写 `zhijian-relations`，禁止散落多处 `localStorage.setItem`。
- **函数归属 / 调用方**：属于**工程实现层**，以架构文档 **D.10** 为准（PRD 不重复声明，避免两处漂移）。产品侧仅约束契约行为。
- **什么时机写**：仅在分析**成功**（`success === true` 且 `analysis` 非空）后写入**一次**。加载中、失败、切换视角（`currentViewParty` 变化）**都不写**。

**哈希实现（不引任何依赖）：**
- **首选**：浏览器原生 Web Crypto `await crypto.subtle.digest('SHA-1', ...)`（异步；`crypto.subtle` 仅 `https`/`localhost` 可用，符合本项目部署场景）。
- **降级**：`crypto.subtle` 不可用时用纯 JS **FNV-1a 32 位**（同步、非加密、仅用于去重，不承担安全职责）。
- 因此 `applyAnalysisToGarden()` 与 `dedupeKey` 计算函数均为 `async`。**不引入任何 npm 包**，不违反 code-quality「零 runtime deps」。

**⚠️ 归属说明（2026 修订）：** `applyAnalysisToGarden()` 最终归属 `src/core/state.js`，由 `src/modules/report.js` 在 `renderReport()` 成功渲染后调用；`src/modules/` 层内**零横向 import**（`input.js`/`garden.js` 互不 import）。产品语义契约不变，仅实现归属见架构文档 D.10。


**写入结构（JSON schema 示例）：**

```jsonc
{
  "family":  { "total": 26, "events": [ /* … */ ] },
  "partner": { "total": 41, "events": [ /* … */ ] },
  "friend":  { "total": 8,  "events": [ /* … */ ] },
  "none":    { "total": 3,  "events": [ /* … */ ] }   // 兜底记录，不计入任何连接带
}

// events[] 中单条 event 的结构：
{
  "id": "evt_1721740800000_a1b2",   // 唯一 id = 时间戳 + 随机后缀
  "at": 1721740800000,               // 写入时间戳（ms）
  "scene": "partner",                // 判定出的目标节点：family|partner|friend|none
  "gain": 10,                        // 本次加给该节点的养分值（定性一致，页面不显示）
  "source": "analysis",              // 来源：analysis | water | animal
  "dedupeKey": "sha1(conversation).slice(0,16)", // 去重键，见下
  "hint": "伴侣"                     // 仅用于内部调试/文案生成，不显示给用户
}
```

**总览与星图解耦：** `zhijian-nurture`（现有点击/浇灌用）**保留为「总量」**；`zhijian-relations.<node>.total` 为**各节点分量**。连接带档位由**该节点的 `total`** 驱动（不再由全局总量驱动，修订 4.3 的取值来源）：

| 节点 `total` 区间 | 连接带档位 |
|---|---|
| 0–33 | 薄（1.5px / 0.28） |
| 34–66 | 中（3px / 0.55） |
| 67+ | 厚（5px / 0.85 + 流动光点） |

> 若某节点不存在（无记录），**不画连接带**（与 4.4 一致）。

**去重规则（重复分析同一段对话）：**

**结论：要去重，且去重键不含明文对话。**

| 步骤 | 规则 |
|---|---|
| 计算键 | `dedupeKey = hash(normalize(conversation)).slice(0,16)`（`hash` 首选 SHA-1 异步、降级 FNV-1a；`normalize` 见 9.6 D9-1） |
| 判重 | 写入前，在该节点 `events` 中查找**相同 `dedupeKey` 且在 24 小时内**的记录 |
| 命中 | **不重复加分**，仅更新该 event 的 `at`，并触发一次极轻的连接带脉冲（让用户感到「我又看了一次」，但养分不虚增） |
| 未命中 | 正常写入并 `total += gain` |
| 超过 24h 的相同对话 | 视为**新的理解**（用户可能重新思考过），允许再次 +gain |

> **隐私一致性：** `dedupeKey` 只存哈希，**不存对话明文**，与产品隐私底线（不存储原始对话）一致。

**写入后的联动：** 写入完成 → 调 `updateRelationshipBands()`（见 4.3）→ 受影响节点的连接带按新档位平滑过渡（800ms）→ 若是首次出现该节点，连接带淡入入场（4.4）。

### 9.6 补充裁定（回应架构师回问，2026 定稿）

**D9-1｜`normalize()` 精确范围（规范定义，2026 修订定稿，工程师照此实现）：**

| 处理 | 字符 | 理由 |
|---|---|---|
| **剥离** | `\u00A0`（不换行空格）、`\u3000`（全角空格） | 微信/富文本粘贴高频噪音，非语义空白 |
| **剥离** | `\u200B-\u200D`（零宽字符）、`\uFEFF`（BOM） | 不可见控制字符，会污染去重键 |
| **剥离** | C0/C1 控制符中**除 `\n` `\t` `\r` 外的其余**（即 `\u0000-\u0008`、`\u000B`、`\u000C`、`\u000E-\u001F`、`\u007F-\u009F`） | 无渲染意义，属噪音 |
| **保留** | `\u000A`（`\n`）、`\u0009`（`\t`）、`\u000D`（`\r`） | **对话结构信息**——§9.2 的 **P4 判定路径靠「对话前 3 行说话人标签」提取线索**，剥掉换行/制表会摧毁分行结构、砍断 P4 链 |
| **归一** | `\r\n` / `\r` → `\n`；所有空白（含剥离后的残留）压缩为单个半角空格 | 统一换行与空白 |
| **不做** | 大小写转换、繁简转换 | 保持语义敏感，避免把「不同对话」误判为同一段 |

> 更新日志：初版误将 `\u0000-\u001F` 整体剥离（含 `\n`/`\t`），会破坏 P4 判定，已按上表修正。

**D9-3｜AI schema 新增 `relation` / `scene` 结构化字段（P2）本轮不做。**

**D9-4｜技术事实确认（`sha1` 同步性）：** 采纳架构师的「**异步 Web Crypto + FNV-1a 降级**」方案。理由：code-quality 明令「零 runtime deps」且禁任何第三方脚本，**不为一个去重键引入 hash 依赖**；去重键不承担安全职责，FNV-1a 碰撞率对「同一段对话是否 24h 内重复」场景完全够用。

## 10.4 五个生态区域规格

### 10.4.0 关键约束：**「变丰富」而非「变大」**

> 产品宪法禁止「升级 / Lv.10 / 越来越大的树」这类强游戏化表达。因此养分的视觉映射**必须是加法（增加元素）而非乘法（缩放）**：
> - ❌ 树冠等比放大 1.5 倍、花丛整体 scale(1.4)
> - ✅ 树干**长出新的一根侧枝**、树冠**多出一团叶**、树洞**从无到有**、**出现一只鸟和鸟巢**

### 10.4.1 家人 · 根系森林（`family`，古树）

- **①视觉元素清单**：主干古树、地表外露根须、树冠叶团、树洞、鸟巢、树下小灯（1–3 盏）、散落松果/果落
- **②建议空间位置**：**中景左侧**，`x≈18–30%`，y 轴落在地平线上方；根须延展至前景地面，是「根系」意象的锚
- **③三态形态差异**：

| 态 | 具体形态描述（只加不缩） |
|---|---|
| **沉淀期** | 一株主干 + 两团稀疏叶；根须短、**仅 2 条**外露；无树洞、无灯、无巢。整体是「还在安静站着」的样子 |
| **生长中** | 叶团增至 3–4 团，**从主干中段长出一根新侧枝**；外露根须增至 4–5 条并向外延伸；**出现树洞（一个小暗口）**；树下**点亮 1 盏小灯**；出现少量果落 |
| **繁盛期** | 叶团封顶（约 5 团，**不再增**）；侧枝 **2 根**；**树洞口出现一只鸟 + 一枚鸟巢**；树下小灯 **2–3 盏**并轻微呼吸；根须与人行小径相连，出现「**一条被踩出来的小路**」通向自我幼苗 |

### 10.4.2 爱人 · 共生花园（`partner`，双株）

- **①视觉元素清单**：**两株并生的花**（一高一低、相互依偎）、花环拱门（藤蔓缠绕）、开放的花瓣、藤蔓延伸、落瓣小径
- **②建议空间位置**：**中景偏右 / 中央偏右上**，`x≈48–62%`；拱门横跨在「我」与爱人的中轴线上，作为视觉上「两个人」的连接物
- **③三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| **沉淀期** | 两株矮小的并生植物，**尚未形成拱门**（仅有藤蔓试探性搭起半弧）；**1 朵**花苞，未开 |
| **生长中** | 拱门**合拢成完整弧形**；两株各 **1–2 朵**开放的花，朝向彼此；藤蔓上结出 1 处小结；落瓣小径初现 |
| **繁盛期** | 拱门**缠绕更密**（不加高度，**加缠绕密度**）；两株各 **2–3 朵**花，出现**一朵同时被两株枝叶托住的花**（「共生」的具体意象）；**出现一根把两株系在一起的细藤**；落瓣小径完整；**出现一只停驻的小鸟**（与家人区的鸟呼应但不重复） |

- **②建议空间位置**：**前景右侧**，`x≈68–88%`，溪流自中景右下流入前景；萤火虫在溪谷上方低空漂浮
- **③三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| **沉淀期** | 小溪是**细细的一线水流**，水面平静；**无鱼**；岸边无可踏的石头；萤火虫 **0–1 只**，且很暗 |
| **生长中** | 溪流**变宽一点并出现弯曲**；**溪中出现 2–3 尾鱼**（游动动效）；岸边出现**可踩的石头**；萤火虫 **2–3 只**，暖白光呼吸 |
| **繁盛期** | 溪流**出现分岔与小水花**（不加大流量，**加细节**）；**鱼增至 4–5 尾**并成群；岸边**长出一座简易小木桥**；萤火虫 **4–6 只**（封顶）；**水边出现一处两个人坐下的小草地**（呼应「朋友是坐得下来的关系」） |

- **②建议空间位置**：**前景左中**，`x≈30–42%`，**必须在自我的幼苗的右侧但不同锚点**（避免 V1 的重叠缺陷，间距 ≥24px）；小栅栏围合出「苗圃」的独立小生境
- **③三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| **沉淀期** | 苗圃里是**一撮刚破土的小芽**，只有两片小叶；小栅栏**只围了三面**（留一个开口）；土面平整 |
| **生长中** | 幼苗**抽高一节、多出一对叶**；**栅栏合围成完整的圈**；土面出现翻动痕迹；**出现一只蝴蝶**停在栅栏上 |
| **繁盛期** | 幼苗成为**一株小树苗**（不是大树，是「苗」的体量）；**叶量增加**并出现**一个花苞**；栅栏旁**多出一把小水壶**（「照料」的具体意象）；**出现一条从苗圃通向自我的小径**；蝴蝶 **2 只** |

## 10.6 「根脉」形态规格（已拍板：直连线 → 根脉）

### 10.6.1 视觉语义

**根脉 = 从「我」这株幼苗的地表根部，向各区域地下/地表延展出去的一束根须。**

- 它不是「数据连线」，也不是「管道」；它是**植物长出来的东西**——是「我」主动伸出去的部分。
- 因此**每一条根脉都从自我出发**（星形拓扑不变，§7 Q1-A 依然成立），**根脉不横向互连**（不画家人↔爱人）。
- 根脉**埋在地表附近**：靠近自我的一端在地表以下（未露出），越靠近目标区域越**抬起并露出地表**，最终**与目标区域的根部/地面相接**。
- 语义定调：**「我伸出去的根，够不够到、够不够牢」**——表达的是**我的投入与这段关系的承载**，而**不是对方的评价**，更不是分数。

### 10.6.2 三档养分 → 根脉粗细与可见度（沿用 `total` 档位，不新增阈值）

| 档位（`total`） | 根脉形态 | 线宽（内部值，不外显） | 可见度 | 附加 |
|---|---|---|---|---|
| **薄（0–33）** | **一根极细的独根**，贴着地表几乎不露出 | `1.5px` | `opacity .28` | 无流动；近似「将伸未伸」 |
| **中（34–66）** | **一根主根 + 2 条小分叉**，显露出地表 | `3px` | `opacity .55` | 静态微光（blur 2px） |
| **厚（67+）** | **主根明显并分出 3–4 条侧根**，地表出现**细小的土壤隆起** | `5px` | `opacity .85` | **沿线缓慢流动的养分光点**（3s 循环）+ 端点极轻呼吸光晕 |

- **过渡**：`transition: stroke-width .8s, opacity .8s`（对应设计系统「颜色过渡 800–1200ms」），**必须可见渐变过程**。
- **首次出现某节点**：根脉由自我端**向外「生长」延伸到位**（600ms），随后有一次极轻的高亮脉冲。
- **长期无记录**：根脉降至「薄」并 `opacity .15`，**保留不删**（不否定用户曾有的关系）。

### 10.6.3 根脉 与「连接带只表达定性感受」的关系（宪法对齐）

**这是同一件事的两种表述，必须严格合并口径：**

| 维度 | 口径 |
|---|---|
| **内部数据** | 仍是 `zhijian-relations.<node>.total` 的**单值**（§9.5 契约不变，数据结构零改动） |
| **视觉载体** | V1 的 `band-line` **改名为 `root-vein`**（语义更准确）；路径仍从自我锚点 → 目标锚点，但**形态改为根须**（更粗的起始端、分叉、贴地行进） |
| **承载信息** | 只承载「**粗细 / 可见度 / 是否流动**」三种**定性**感受 |
| **绝不承载** | 不显示数字、不显示百分比、不支持 hover 出数值、不做「进度条化」 |
| **与形态的关系** | 根脉三档 与 区域三态 **同源同档**（同一个 `total` 同时驱动），保证「根粗了 ↔ 那处也长丰富了」**因果可读** |
| **实现提示（非需求）** | 用内联 SVG `<path>`；根须形态用 `stroke-linecap: round` + 沿路径的细支路（同一 `<path>` 多段 `M...Q...`），`vector-effect="non-scaling-stroke"` 防拉伸 |

> **一句话**：根脉只是**把 V1 的连接带换成更符合「花园」隐喻的形态**，它表达的仍然是「我在这段关系上伸出去多少」，**不是对方如何，也不是一个分数**。

## 10.7 三能量体系评估（理解 / 修复 / 连接）—— **最终结论**

**结论：采纳你的倾向。引入三分法，但只作为「来源标记」，不作为三套独立数值。全系统仍只有单一 `total`。**

### 10.7.1 为什么不做三套独立数值

| 代价 | 说明 |
|---|---|
| **宪法风险** | 三套独立数值必然被呈现为三个可比数字 → 直接踩 A2/A3/A4 的分数禁令；即便不显示数字，也极易被做成三条进度条 |
| **复杂度爆炸** | 连接带/根脉粗细（1 值）→ 形态三态（1 值）→ 三能量（3 值）会出现 **3 个独立阈值系统**；用户看不懂「理解够了但修复不够」时花园到底长不长 |
| **数据不足** | 单条事件的 `gain` 只有 10，拆成三份后每份 3–4，**噪声远大于信号**，波动会显得随机 |
| **与 §9.4「主轴 100/0」冲突** | 我们已裁定一次分析只给一个节点 100% 养分；再拆成三能量比例，等于**在错误的地方重新引入了「半亮」问题** |
| **对用户无增量价值** | 用户真正想知道的是「**这次我多懂了一点什么**」，而不是「我这次理解分涨了 1.7」 |

### 10.7.2 采纳方案（正式规格）

**唯一总量 + 单一来源标记：**

```
zhijian-relations.<node>.total          // 唯一总量，驱动根脉粗细 + 区域形态三态（不变）
zhijian-relations.<node>.events[i].source   // 既有字段：analysis | water | animal（不变）
zhijian-relations.<node>.events[i].energy   // 新增：'understand' | 'repair' | 'connect'
```

- **`energy` 是每一条 event 上的一个枚举标记**，**不参与任何数值计算**，**不驱动任何视觉档位**。
- **判定来源**：优先取 AI 已返回的情绪/责任分布信号的**定性归因**（若可用）；否则**兜底规则**（确定性、可测）：

| 事件特征 | 标记为 |
|---|---|
| 以「倾听 / 说出真实感受 / 看清自己」为主 | `understand` |
| 以「争执后缓和 / 道歉 / 重新开始对话」为主 | `repair` |
| 以「久未联系后的重新靠近 / 主动发起」为主 | `connect` |
| 无法判定 | `understand`（缺省，不新增第四类） |

### 10.7.3 三分法的唯一用途：**差异化文案（不给数字）**

| 用途 | 具体表现 |
|---|---|
| **记忆卡（故事卡）** | 卡片上一枚**内联 SVG 小图标**（三种形状：镜/缝合线/连线）**仅作来源标识**，无数字、无百分比 |
| **生长建议的开场句** | `understand` → 「你已经看见了不少，接下来可以试着说出来」；`repair` → 「有些裂痕已经开始愈合，可以先从小事说起」；`connect` → 「你们重新连上了，接下来把它变成习惯」 |
| **顶部本期摘要**（对应 A2/A3/A4） | 三条定性短句**轮播**（不做同屏三列对比），避免被读成三个并列指标 |

> **落地约束**：`energy` 字段**不得**出现在任何排序、任何阈值判断、任何宽度计算里。它是**纯文案元数据**。

## 10.8 首次进入的空状态（首次生长动效）

**原则（对齐参考图设计提示词）：不要一次给完整花园。首次进入是「冬季 · 尚未生长」的空白空间，只有一株很小的「我」。**

### 10.8.1 空状态规格

| 项 | 规格 |
|---|---|
| 场景 | **冬季氛围**（对应 `SEASONS[0] = 冬 · 沉淀季`）：雾蓝调、光更淡、光斑少、地面留大片留白 |
| 唯一生命体 | **自我 · 幼苗**（`self`）——高度约 42px（沿用现有 `.sprout` 尺度），**比其他任何版本都更小**，居中央偏下 |
| 五个区域 | **全部不存在**（不是灰色占位、不是虚线轮廓）——画面里就只有一株幼苗与空空的土地，以及远景一座雾山 |
| 根脉 | **零条**（无任何 `root-vein`） |
| 文案 | 主句：「**这里还是一片空地。**」副句：「**说一段话，它会开始长。**」（引导去输入页，不催促、不打分） |
| 导航 | 底部导航正常可用；`+ 倾诉` 主 CTA 唯一高亮 |
| 禁止 | 不得出现任何灰色占位圈、骨架屏、进度提示、`0/5 已完成`类文案 |

### 10.8.2 首次生长动效节奏（第一次分析成功后，总时长约 **3.4s**）

| 时间 | 动作 | 动效细节 |
|---|---|---|
| `0ms` | 场景**季节切换**（冬 → 当前真实季节） | 雾蓝 → 晨曦金，色温过渡 **1200ms**（设计系统上限） |
| `300ms` | 空地上**先落下一片土壤隆起** | 极轻的 `.seedling-mound` 波纹扩散，400ms |
| `700ms` | **自我幼苗抽高一节** | scale 不变，**加一对叶**；400ms，`cubic-bezier(.4,0,.2,1)` |
| `1200ms` | **第一条根脉从幼苗根部向目标区域「生长」延伸** | `stroke-dashoffset` 动画 600ms，由自我向外 |
| `1800ms` | **目标区域的生命体「长出来」** | 淡入 + 轻微上浮（≤8px），600ms；**不是弹跳、不是缩放放大** |
| `2400ms` | 该区域的**标签胶囊**淡入 | 200ms，`opacity 0 → 1` |
| `2800ms` | **一次极轻的全场暖光脉冲** | 300ms 后回落，表示「花园醒了」 |
| `3400ms` | 结束 | 之后**不再重放**（存 localStorage 标记，见下） |

- **触发条件**：仅当 `zhijian-relations` 从「全空」变为「有 ≥1 个节点有事件」时播放一次。
- **幂等标记**：`zhijian-garden-first-growth = '1'`，播放后写入；重复进入不重放。
- **可跳过**：若用户此时已离开花园页，**不阻塞、不排队**，下次进入直接看终态。
- **无障碍**：尊重 `prefers-reduced-motion: reduce` → 全部动效降为**直接切换终态**（0ms）。

## 10.9 四季的呈现判断（独立页 vs 内嵌）—— **最终结论**

**结论：四季「不新增独立页」，做内嵌氛围层 + 一个可随时打开的「花园季节」**轻浮层**。**

### 10.9.1 理由

| # | 理由 |
|:--:|---|
| 1 | **现有代码已内嵌**：`garden.js` 已有 `SEASONS` 常量 + `getSeasonIndex()` 按月份自动映射（12–2 冬 / 3–5 春 / 6–8 夏 / 9–11 秋）。改独立页 = **推翻已跑通的自动季节逻辑**，并额外处理「独立页季节 ≠ 时间季节」的矛盾 |
| 2 | **独立页违反产品语义**：产品是「打开花园就看到我的关系」，不是「去季节页看进度」。四季若成独立页，会被读成**关卡/赛季**（踩 B4） |
| 3 | **信息密度不足撑一页**：四季的信息量 = **色温 + 文案 + 少量粒子**，做成整屏页会显得空，反而催生「加进度条填充」的冲动（踩 A6） |
| 4 | **已有 `SEASONS[3] = 秋 · 收获季` 的措辞可用**，无需新建体系 |
| 5 | **不阻断主路径**：用户的主路径是「花园 → 拿一朵浮层胶囊看得更清楚」，不应被一个季节页打断 |

### 10.9.2 落地规格

| 项 | 规格 |
|---|---|
| **主形态** | **内嵌氛围层**（沿用 §4.5 的四季氛围参数表）：季节 = 色温 + 光斑密度 + 状态文案，**永不显示数字/进度条** |
| **入口** | 顶部季节状态处「**初春 · 正在生长**」是一枚**可点击的文本按钮**（无图标、无箭头堆叠） |
| **展开形态** | **轻浮层（bottom sheet）**，高约 40% 屏，四行：`冬 · 沉淀季 / 春 · 生长季 / 夏 · 繁盛季 / 秋 · 收获季` |
| **浮层内容** | 每行 = 当前季节**定性描述一句**（如「土地在休息，根在往下走」） + `当前` 标记（**不是选中态、不可切换**） |
| **是否允许用户切换季节** | **不允许。** 四季由**当前月份 + 关系生长状态**共同决定（推进规则沿用 §4.5），**不是用户可调设置**——否则会变成「主题皮肤」，失去叙事 |
| **与 `SEASONS` 的关系** | **完全复用** `SEASONS` 与 `getSeasonIndex()`；浮层只是**把已有常量可视化**，零新增数据 |
| **参考图「冬春夏秋四选」** | **不采纳**（会引入「自由切换 → 皮肤化 → 游戏化」三重风险）；若未来确有需要，须先拍板「季节是否还是叙事」 |

## 10.10 关系记忆光点（故事卡）

### 10.10.1 触发条件

| 项 | 规则 |
|---|---|
| **光点从哪来** | 每条 `event` 在对应区域的生命体周围**生成 1 枚光点**（不是每条 event 一枚——见上限） |
| **位置** | 漂浮在该区域生命体**周围 20–60px 的环形带**内，位置由 `event.id` 哈希决定（**稳定不跳动**，避免每次渲染乱飞） |
| **产生条件** | 仅 `source === 'analysis'` 的 event 生成光点（**点击浇灌的 `water` / 选动物的 `animal` 不生成**，否则光点会泛滥） |
| **点击** | 点击光点 → 弹出**故事卡**（浮层，居中或底部 sheet） |
| **可点击性** | 光点触控目标 **≥ 44px**（视觉可小，但热区必须达标，符合 design-system-guard 第八节） |

### 10.10.2 上限（防光点泛滥）——**关键约束**

| 规则 | 值 |
|---|---|
| **单区域光点上限** | **3 枚**（超出后只保留**最近 3 条** `analysis` event 对应的光点） |
| **全园光点上限** | **12 枚**（5 区域 × 上限即为上限，实际由单区 3 枚自然约束） |
| **超过上限的 event** | **不消失、不删除**——仍存在于账本、仍见于「情境回顾」列表，只是**不再有独立光点**；被合并进「更早的记忆」聚合卡 |
| **聚合卡** | 当某区域 `analysis` event > 3 条时，额外出现 **1 枚略暗的聚合光点**，标题「**更早的一些记忆**」，内部列出更早条目的日期 + 一句话摘要（可滚动） |
| **总光点上限（含聚合）** | 单区域 **≤ 4 枚**（3 最近 + 1 聚合） |

### 10.10.3 单卡信息结构（故事卡）

| 位置 | 内容 | 约束 |
|---|---|---|
| 顶部 | **关系图标（内联 SVG）+ 关系名 + 时间**（如 `家人 · 2026年3月`） | 时间只到**月**（不精确到日，降低「被记录」的压迫感） |
| 中部 | **一句定性叙述**（见模板） | ≤40 字，**行为描述**，**无评判、无分数** |
| 中部下方 | **一枚能量来源小图标**（`understand/repair/connect` 三选一）+ 对应短语 | **仅来源标识，无数字**（见 §10.7.3） |
| 底部 | **一个「成长建议」入口**（文本按钮） | 文案「**要不要试试这样说**」，点击进入对应建议（不叫「改进计划」） |
| 关闭 | 点击遮罩 / 关闭按钮 | 不做「左滑跳下一条」的强引导（避免变成刷 feed） |

### 10.10.4 文案模板（3 类 × 各 2 例）

> 模板变量：`{关系名}`、`{月份}`、`{行为描述}`。**行为描述必须是可观察的行为，不做人格结论、不判对错。**

**`understand`（理解来源）**
- 「{月份}，你在和{关系名}的那次对话里，**第一次看清了自己当时为什么会沉默**。」
- 「{月份}，你试着**把说不出口的那层意思讲清楚了**，对方听见了。」

**`repair`（修复来源）**
- 「{月份}，一次不太愉快的对话之后，**是你先递出了那句话**。」
- 「{月份}，你们把一段僵着的话**重新说开了**，虽然还没完全顺过来。」

**`connect`（连接来源）**
- 「{月份}，你**第一次主动和{关系名}聊起了最近的压力**。」
- 「{月份}，隔了一阵没联系之后，**你发了那条消息**。」

> ⚠️ 模板禁用词：任何分数、任何「成功/失败」、任何「你错了/是你的问题」、任何人格标签、任何侮辱性词（对齐 product-principles 第二节）。

### 10.10.5 独立页「爱人 · 共生花园详情页」适配

参考图的独立详情页（关系状态 **72%** 环 / 最近的故事 / 成长建议 / 关系练习）**不新增独立页**，改为**故事卡 + 区域浮层**的聚合形态：

| 参考图元素 | 合规落地 |
|---|---|
| 关系状态 **72%** 环 | **删除环**。改为一句定性 + 一段**无刻度柔和色带曲线**（对应 A6/A7） |
| 最近的故事 | = 该区域的**光点列表**（最多 3 + 聚合），即 §10.10 |
| 成长建议 | 沿用「**成长建议**」术语，入口文案「要不要试试这样说」 |
| 关系练习按钮 | 保留文案「**关系练习**」，副文案邀请式；**不引入任何完成度/打卡** |
| 是否独立整屏页 | **否**——以**区域浮层**（bottom sheet）承载，从区域内生命体或光点进入，**不新增路由** |

### 已定稿（team-lead 已裁定，不得再翻案）

**Q-V2-1｜「关系温度」→ ✅ 采纳「保留但四档定性」。已定稿。**

- 四档词：`还很安静 / 有些暖意 / 正在靠近 / 温暖`
- **追加约束一（team-lead 提出，已写入）**：四档文案**不是数值区间的变相**。特别禁止「温暖 / 很温暖 / 非常温暖」这类**递进感过强的排序暗示**——那等于把分数换了个说法。四档必须是**四种不同的状态**，而不是**同一个形容词的四级程度**：
  | 档 | 文案 | 为什么它不是「程度递进」 |
  |---|---|---|
  | 一 | 还很安静 | **状态**：没什么动静 |
  | 二 | 有些暖意 | **状态**：有了一点温度 |
  | 三 | 正在靠近 | **状态+方向**：在往一起走 |
  | 四 | 温暖 | **状态**：已经是暖的 |
  > 注意三档是「靠近」（方向），不是「更暖」（程度）——这是本组文案的设计要点。
- **追加约束二（team-lead 提出，已写入）**：温度档位**不得驱动任何视觉档位**——**沿用 `energy` 字段的同款约束**：不参与任何阈值判断、不参与任何宽度/透明度计算、不出现在任何排序里。它**只驱动一句文案 + 一处色温**，是纯氛围元数据。
- 逻辑上：它与 `total` **不是同一个值**，不显示、不参与计算，与 §10.7 的 `energy` 约束同源。

**Q-V2-2｜底部导航第 3 项 → ✅ 采纳「保留『记录』」，不采纳「洞察」。已定稿。**

- **理由（team-lead 裁定原文，写入此处以防下一轮再被提议）**：
  > 这是一款强调「**看见自己**」的产品，「洞察」带有「**我给你结论**」的**俯视感**，与产品气质相悖；「记录」更中性、更贴近**用户自身的动作**。
- 补充一致性：`记录` 与现有术语「**情境回顾**」（用户回看自己的记录）语义连贯；`洞察` 则贴近「**数据看板 / 分析结论**」，与 §8 的术语禁止清单张力更大。
- **结论：导航四项 = 花园 / 记录 / 倾诉 / 我的（图标全部改内联 SVG，无 emoji）。**
  > 注：V1 现网导航为「花园 / 倾诉 / 记录 / 我的」（见代码基线 §二）。V2 若按参考图调整为「花园 / 记录 / 洞察 / 我的」，**第 3 项必须落为「记录」**；建议**维持 V1 既有顺序**，仅在必要时调整，减少无效改动。

**Q-V2-5｜首次生长动效 → ✅ 采纳「不提供跳过按钮」。已定稿。**
