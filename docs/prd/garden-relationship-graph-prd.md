## 2. 背景与诊断

问题**不在美观，而在信息设计**。当前古树/花丛/动物/幼苗被画成**四个彼此孤立的装饰物**，之间**没有任何视觉连接**。产品核心隐喻是「**关系**花园」，用户应看见的**关系**被丢失了——画面传达的是「这里有四株植物」，而不是「关系在生长」。

**一句话目标（可验证）：**
> 用户打开花园页后，能在 3 秒内指出「自我」与某个重要的人之间**至少一条可见的连接**，并能说出这条连接的强弱变化代表这段关系的养分状态。

V2 目标升级为：
> 用户打开 V2 花园，第一眼看到的是**一片有纵深、有五个生态区域的 2.5D 关系地貌**（而非排列的装饰物），并能通过**五个生命体的形态丰富度**与**从自我幼苗长出的根脉**，直观感知「哪段关系有养分、哪段淡」，**全屏找不到任何一个数字、百分比或进度条**。

---

## 3. 产品目标（三个正交）

- **G1 可见关系（生态地形）**：把「并列排布的孤立角色」重构为**一张有中心、有连接的关系图 / 一片有纵深的生态地貌**，用户能「走进」而不是「看板式浏览」。
- **G2 可见生长（形态丰富度）**：让「关系养分」与花园画面产生直接视觉联动。V1 用「连线变粗」表达，V2 升级为「**生命体变丰富**」——新增枝 / 花 / 果 / 巢 / 洞 / 新生命，**严禁等比放大**。这是本次最重要的视觉语义升级。
- **G3 宪法零冲突**：画面中所有可能出现的分数化、游戏化、强激励化表达，**全部替换为定性表达**（见第 8 章逐条适配表），一条不漏；同时消除 emoji/CSS 混用、锚点重叠、树冠越界等**体验缺陷**。

**验证方式（验收时执行）：**
1. 截图花园页 → 存在**可辨的前景 / 中景 / 远景三层纵深**；五个生态区域各自可辨；画面中存在**可辨的、连接自我与角色的根脉**（非装饰纹理）。
2. 养分由低至高变化 → **生命体形态由「沉淀期」进化到「繁盛期」，且变化是「变丰富」（新增元素）而非「变大」**；根脉的粗细/亮度呈可辨的三级差异。
3. 全屏扫描：**不含任何分数、百分比、进度环、进度条**；无禁用术语、无 emoji、无人格/道德/侮辱性表述。

## 4. 用户故事

- **US1｜看见关系**：作为刚完成一次「情境回顾」的用户，我希望打开花园就能看到「我」与每个重要的人之间有**一道连接**，以便直观感受到「这段关系是活跃的 / 淡的 / 正在恢复」。
- **US2｜看见生长**：作为持续使用知间的用户，我希望当我的**关系养分**增加时，花园里的连接/生命体**变得更丰富**，以便感到「我的努力真的让关系变化了」。
- **US3｜看见部分**：作为只填写了「情侣吵架」场景的用户，我希望花园里**只出现我和伴侣的关系**，而**不是显示一堆孤零零的植物**，以便画面诚实反映我当前记录的关系。
- **US4｜看见时间**：作为多次回来的用户，我希望花园能呈现「**季节**」氛围（如春·生长季 / 秋·收获季），以便感知到我在知间陪这段关系走过了一段时间。

## 6. 六类关系模型

### 6.1 六类关系（关系分类的产品定义）

关系花园把用户记录的关系归为**六类**，其中五类各对应一个生态区域，一类为兜底：

| 关系类别 | 花园内的呈现名 | 生命体主体 |
|---|---|---|
| 家人 | 家人 · 根系森林 | 古树 |
| 爱人 | 爱人 · 共生花园 | 双株 |
| 朋友 | 朋友 · 流动溪谷 | 溪流 + 小动物 |
| 孩子 | 孩子 · 新生苗圃 | 幼苗 + 小栅栏 |
| 同事 | 同事 · 林间营地 | 帐篷 + 篝火 |
| 兜底（无名记录） | （无区域） | 落叶 / 无名花 |

- **家人与爱人是两个独立类别**，不可互相合并。
- **子女不归入「家人」**：孩子是「新生苗圃」这一**独立生态区域**；父母与兄弟姐妹仍归「家人」（古树 = 家人）。花园不为每个家人单独建区域，仅累积到各自区域的一条根脉。
- **职场关系不归入兜底**：职场是**存在的关系**，归「同事」；兜底专用于「陌生人 / 服务人员 / 无法判断」——即**本就不存在长期关系**的情形。

### 6.2 场景 → 关系类别映射

> 映射规则只决定「养分加给哪一类关系」，**绝不向用户暴露任何分数**——花园里只体现定性感受（淡 / 明显 / 明亮）。

| # | 场景类型（用户心智） | 典型称呼词线索 | 目标关系类别 |
|:--:|---|---|:--:|
| 1 | 与父母 / 长辈（爸妈、公婆、岳父母、爷爷奶奶等） | 妈 / 爸 / 婆婆 / 公公 / 家里 / 养老 | 家人 |
| 2 | 与配偶 / 伴侣 / 恋人 | 老公 / 老婆 / 男朋友 / 女朋友 / 对象 / 亲爱的 / 咱俩 / 结婚 | 爱人 |
| 3 | 与子女（含继子女、养子女） | 孩子 / 儿子 / 女儿 / 宝宝 / 上学 / 作业 | **孩子** |
| 4 | 与兄弟姐妹 / 其他亲属 | 哥 / 姐 / 弟 / 妹 / 姑姑 / 叔叔 / 表哥 / 亲戚 | 家人 |
| 5 | 与好友 / 闺蜜 / 发小 / 同学 | 兄弟 / 姐妹 / 闺蜜 / 发小 / 老同学 / 朋友 | 朋友 |
| 6 | 与同事 / 上司 / 下属 / 合作伙伴（职场摩擦） | 领导 / 老板 / 同事 / 项目 / 开会 / 绩效 / 客户 | **同事** |
| 7 | 与陌生人 / 服务人员 / 网络争执 | 客服 / 快递 / 司机 / 网友 / 路人 | 兜底 |
| 8 | 无法判断 / 混合 / 其他 | 无有效线索 | 兜底 |

> **称呼词线索纪律**：关键词词典**只收录中性称呼词**。禁止收录「妈宝 / 扶弟魔 / 凤凰男 / 原生家庭 / 创伤 / 控制狂」等诊断性、审判性、侮辱性词汇；若用户原文出现此类词，**只做内部计数、绝不回显、绝不进入任何 UI 文案**。

### 6.3 判定依据的优先级（无显式选择时的推断顺序）

系统按下列优先级**逐级判定**（命中即止，低优先级不再参与）：

| 优先级 | 依据 | 命中条件 |
|:--:|---|---|
| P1 | 用户显式选择「这段对话是关于…」 | 用户明确选了场景 |
| P2 | AI 返回的结构化关系信号 | 字段存在且非空 |
| P3 | AI 输出文本中的关键词 | 经称呼词词典匹配，命中唯一类别 |
| P4 | 用户粘贴原文中的关键词 | 命中唯一类别 |
| P5 | 兜底 | 以上均未唯一命中 → 兜底 |

### 6.4 冲突消解与截胡防线（G1–G4）

**当一段对话同时涉及多类关系时，只认定一个「主轴关系」，全部养分给主轴，不拆分、不按比例分配。**

**（a）冲突消解的顺序依据（六类全序）：**

`爱人 > 孩子 > 家人 > 同事 > 朋友 > 兜底`

> **排序依据（这是产品价值判断，不是亲密度打分）**：按「对话直接参与方的亲密与责任强度」排序——伴侣与子女是**同一生活单元内、责任最重**的关系；父母/兄弟姐妹次之（有血缘但常非共同生活）；同事是**高频共处但边界清晰**的关系；朋友是**低频但自愿**的关系；兜底最后。
> 这与「直接参与方优先」原则一致——**不是按亲密度打分，而是按「这段话里，谁是在场的那个人」排序**。

**（b）四条截胡防线 G1–G4（防止泛指词抢走限定词的主轴）：**

| 编号 | 规则 | 说明 |
|:--:|---|---|
| **G1** | **限定词优先于泛指词** | 「孩子」词典（孩子/儿子/女儿/宝宝/上学/作业）与「家人」词典（妈/爸/婆婆/公公/家里）同时命中时，**先判「这段话的直接参与方是谁」**：若参与方是子女（如「辅导作业时和儿子吵了」），主轴 = 孩子，即使句中出现「妈」也只作**背景提及**、**不参与主轴竞争** |
| **G2** | **「同事」专属词短路（须带前置条件）** | 命中「同事」**专属词**（领导/老板/同事/项目/开会/绩效/客户/加班/汇报）**且**「直接参与方是职场关系」时，**直接短路到同事**，不再进入与其他类别的次数比较。（注意）**缺一不可**——只看词不看参与方会误吞「我老婆嫌我加班多」（见 H3/H4） |
| **G3** | **「家人」与「孩子」的判定顺序固定** | 先判**孩子**（检查是否有子代参与方线索），**再**判**家人**。顺序固定、不得颠倒——这是「规则顺序导致截胡」的唯一根治方式 |
| **G4** | **兜底只在最后一步产生，不得被 P3/P4 直接命中** | P3/P4 阶段**禁止**把未唯一命中的结果直接写成兜底；必须走完 P1→P4 全部路径且**确认无任何类别命中**，才落兜底 |

> **「次数最多者优先」不再作为主判据**：当命中词分属「家人」与「孩子」时，**次数不参与竞争**，一律由 G3 的顺序 + G1 的「直接参与方」决定。次数的意义仅用于**同一类别内部的置信度**，不用于跨类别抢主轴。

**（c）为什么是「主轴 100/0」而非「按比例分配」：**
- 「按比例 50/50」会让花园出现**半亮的连接**，用户无法理解其含义，也**极易被误读成分数**（违反宪法与术语纪律）。
- 主轴规则与「星形拓扑」一致：自我是原点，一次对话只在**一段关系**上留下痕迹，语义清晰。
- 副轴信息不丢失：它仍体现在报告页的「情境回顾」里，只是**不写进关系花园的养分账本**。

**（d）G2 修正版（重要，防止「同事」误吞）：**
> 仅当「同事」专属词命中的**同时**，判定「**对话的直接参与方是职场关系**」（说话人标签/参与方线索指向同事、领导、下属、客户等），才短路到同事。**若专属词只是出现在话题里（如「我老婆」「我妈」明确在场），专属词不参与短路。**

### 6.5 兜底（无名记录）

**结论：判定不出目标关系时，不加给任何关系，但在花园里留下一次「无名记录」，且该记录不进入任何关系养分。**

**为什么这样定（产品裁量理由，本文档为唯一出处）：**
- 强行塞进「家人/爱人/朋友」会造成**语义污染**——把职场冲突记成「家人关系生长」，用户会不信任花园。
- 但**完全丢弃**会让用户觉得「白分析一场」，破坏「每次理解都是水」的核心隐喻。
- 因此折中：**留下无归属的「无名记忆」**，既诚实（不臆造关系）又有温度（不至于空手而归）。
- V2 补充：这条折中仅适用于「真的没有长期关系」的情形；职场与子女都已有各自类别，不属于此列。

**兜底的表现与约束：**
- 花园表现：飘落 1 片落叶，或以一枝无名小花点缀。
- 养分归属：只增**关系养分的总量**，**不增任一类关系的养分**。
- 文案（定性、无分数）：「这次对话，你也在认真看见自己」。
- **准入条件**（必须是「本就不存在长期关系」）：与陌生人 / 客服 / 快递 / 司机 / 网友 / 路人；或线索不足无法判断；或多类关系混合且无直接参与方。判定兜底前必须确认 **G1–G4 四条防线已全部走完**。
- **追加约束**：落叶/无名花**上限 5 个**，超出不再叠加；且**永不**连出根脉。

### 6.6 多目标处理（逐格判定示例）

**规则：一次分析只认定一个「主轴关系」，全部养分（100%）加给主轴的唯一类别；不拆分、不按比例分配。**

| 情形 | 处理 |
|---|---|
| 同时涉及「家人」和「爱人」（如夫妻讨论与公婆的关系） | 主轴 = **爱人**。理由：对话的**直接参与方**是伴侣，冲突发生在两人之间；与父母的关系是**背景议题**。 |
| 同时涉及「爱人」和「朋友」 | 主轴 = **爱人**（直接参与方优先）。 |
| 同时涉及「家人」和「朋友」 | 主轴 = **家人**。 |
| 同时涉及「子女」和「爱人」（如夫妻争论怎么管孩子） | 主轴 = **爱人**。理由：**同辈的直接参与方是伴侣**；孩子是**议题**。**例外**：若对话直接发生在一方与孩子之间（如「我和儿子吵架了」），主轴 = **孩子**。 |
| 同时涉及「子女」和「父母」（如「我妈总干涉我怎么管孩子」） | 主轴 = **家人**。理由：**直接参与方是「我妈」**；孩子是**被干涉的议题**，不是在场的那一方。**这是「家人」与「孩子」最易混淆的一格，按「谁在场」而非「谁被提到」判定。** |
| 同时涉及「同事」和「朋友」（如「我和同事以前是朋友」） | 主轴 = **同事**（G2 强命中断路优先）。 |
| 同时涉及「同事」和家人/爱人（如「我老婆嫌我加班太多」） | 主轴 = **爱人**。理由：**直接参与方是伴侣**；「加班」只是话题。**注意：此处不得因命中「加班」就短路到「同事」——G2 短路仅在「对话发生在职场关系之间」时生效。** |
| 多人对话（3–5 方）且跨类别 | 取**参与人数最多的那一类关系**为主轴；并列时按六类全序消解。 |

## 7. 关系花园（V2）视觉与交互规格

### 7.1 五生态区域规格

#### 7.1.0 关键约束：「变丰富」而非「变大」

> 产品宪法禁止「升级 / 等级 / 越来越大的树」这类强游戏化表达。因此养分的视觉映射**必须是加法（增加元素）而非乘法（缩放）**：
> - 【禁用】 树冠等比放大、花丛整体放大
> - 【采用】 树干**长出新的一根侧枝**、树冠**多出一团叶**、树洞**从无到有**、**出现一只鸟和鸟巢**
> - 形态总量**有上限**（繁盛期即封顶），避免无限膨胀变成「怪物树」

**三态命名**（统一，替换参考图的分数档）：`沉淀期 / 生长中 / 繁盛期`。三态由**该关系类别的养分分量**驱动，且**根脉与区域形态同源同档**（同一个养分分量同时驱动二者），保证「根粗了 ↔ 那处也长丰富了」**因果可读**。

> **养分档位边界（产品-架构共识锚点）**：三态对应养分分量的 `薄 / 中 / 厚` 三档；档位边界值（0–33 / 34–66 / 67+）为产品与架构共用的一致性锚点，**具体映射实现见架构文档**。此处保留边界仅为跨文档一致，不作为对外展示。

#### 7.1.1 家人 · 根系森林（古树）

- **视觉元素**：主干古树、地表外露根须、树冠叶团、树洞、鸟巢、树下小灯、散落松果/果落。
- **空间定位（定性）**：**中景左侧**，根须延展至前景地面，是「根系」意象的锚。
- **三态形态差异（只加不缩）**：

| 态 | 具体形态描述 |
|---|---|
| 沉淀期 | 一株主干 + 两团稀疏叶；根须短、**仅 2 条**外露；无树洞、无灯、无巢。整体是「还在安静站着」的样子 |
| 生长中 | 叶团增至 3–4 团，**从主干中段长出一根新侧枝**；外露根须增至 4–5 条并向外延伸；**出现树洞**；树下**点亮 1 盏小灯**；出现少量果落 |
| 繁盛期 | 叶团封顶（约 5 团，**不再增**）；侧枝 **2 根**；**树洞口出现一只鸟 + 一枚鸟巢**；树下小灯 **2–3 盏**并轻微呼吸；根须与人行小径相连，出现「**一条被踩出来的小路**」通向自我幼苗 |

#### 7.1.2 爱人 · 共生花园（双株）

- **视觉元素**：两株并生的花（一高一低、相互依偎）、花环拱门（藤蔓缠绕）、开放的花瓣、藤蔓延伸、落瓣小径。
- **空间定位（定性）**：**中景偏右 / 中央偏右上**；拱门横跨在「我」与爱人之间，作为视觉上的连接物。
- **三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| 沉淀期 | 两株矮小的并生植物，**尚未形成拱门**（仅藤蔓试探性搭起半弧）；**1 朵**花苞，未开 |
| 生长中 | 拱门**合拢成完整弧形**；两株各 **1–2 朵**开放的花，朝向彼此；藤蔓上结出 1 处小结；落瓣小径初现 |
| 繁盛期 | 拱门**缠绕更密**（不加高度，**加缠绕密度**）；两株各 **2–3 朵**花，出现**一朵同时被两株枝叶托住的花**（「共生」的具体意象）；**出现一根把两株系在一起的细藤**；落瓣小径完整；**出现一只停驻的小鸟** |

#### 7.1.3 朋友 · 流动溪谷（溪流 + 小动物）

- **视觉元素**：一条从远处流向前景的小溪、溪中石头、鱼、岸边萤火虫、一座小木桥（可选）、岸边草地、溪边可点选的小动物。
- **空间定位（定性）**：**前景右侧**；溪流自中景右下流入前景；萤火虫在溪谷上方低空漂浮。
- **三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| 沉淀期 | 小溪是**细细的一线水流**，水面平静；**无鱼**；岸边无可踏的石头；萤火虫 **0–1 只**，且很暗 |
| 生长中 | 溪流**变宽一点并出现弯曲**；**溪中出现 2–3 尾鱼**（游动动效）；岸边出现**可踩的石头**；萤火虫 **2–3 只**，暖白光呼吸 |
| 繁盛期 | 溪流**出现分岔与小水花**（不加大流量，**加细节**）；**鱼增至 4–5 尾**并成群；岸边**长出一座简易小木桥**；萤火虫 **4–6 只**（封顶）；**水边出现一处两个人坐下的小草地**（呼应「朋友是坐得下来的关系」） |

#### 7.1.4 孩子 · 新生苗圃（幼苗 + 小栅栏）

- **视觉元素**：一棵小幼苗、一圈低矮小栅栏、苗圃翻过的土、浇水小壶（静态）、一只蝴蝶。
- **空间定位（定性）**：**前景左中**，**必须在自我幼苗的右侧但不同位置**（避免重叠缺陷）；小栅栏围合出「苗圃」的独立小生境。
- **三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| 沉淀期 | 苗圃里是**一撮刚破土的小芽**，只有两片小叶；小栅栏**只围了三面**（留一个开口）；土面平整 |
| 生长中 | 幼苗**抽高一节、多出一对叶**；**栅栏合围成完整的圈**；土面出现翻动痕迹；**出现一只蝴蝶**停在栅栏上 |
| 繁盛期 | 幼苗成为**一株小树苗**（不是大树，是「苗」的体量）；**叶量增加**并出现**一个花苞**；栅栏旁**多出一把小水壶**（「照料」的具体意象）；**出现一条从苗圃通向自我的小径**；蝴蝶 **2 只** |

> （注意）孩子区域的形态**必须明显小于家人古树**——语义上「孩子在长，还不是大树」，绝不与古树比肩。

#### 7.1.5 同事 · 林间营地（帐篷 + 篝火）

- **视觉元素**：一顶帐篷、一处篝火（暖橙呼吸）、几根待燃的木材、一条通往营地的林间小径、远处树影。
- **空间定位（定性）**：**远景偏右**，纵深感最强；营地整体偏冷色，**篝火是唯一的暖点**。
- **三态形态差异**：

| 态 | 具体形态描述 |
|---|---|
| 沉淀期 | **一顶未撑开的帐篷**；**篝火未点燃**（只有一圈石与木材）；无小径 |
| 生长中 | 帐篷**被撑起并出现门帘**；**篝火点燃**（低矮、暖橙、慢呼吸）；地上**出现一块垫石**；**踏出一条模糊的小径** |
| 繁盛期 | 帐篷旁**多出一顶小帐篷**（不放大原帐篷，**加数量**）；篝火**更稳并出现细小火星上浮**（低饱和暖色）；**出现两把可坐的木头**（「能坐下来聊」的具体意象）；小径**清晰可走**；**营地与朋友溪谷之间出现一条可见的岔路**（暗示职场关系与友情的界线与相通） |

> **语义定调**：营地是**「在工作的地方，也有人的温度」**，不是「战斗/职场如战场」。因此**禁用**任何武器、防御工事、警戒线、冷硬金属的视觉母题。

#### 7.1.6 五区域的整体构图（纵深）

| 层 | 区域 | 纵深感处理 |
|---|---|---|
| **远景** | 同事 · 林间营地 | 最小尺度、最冷色、最模糊 |
| **中景** | 家人 · 根系森林 / 爱人 · 共生花园 | 主体尺度、色彩最实；古树在左、双株在右，中间留出「我」与爱人拱门的中轴 |
| **前景** | 孩子 · 新生苗圃 / 朋友 · 流动溪谷 | 最大尺度、最暖光、最清晰；溪流从右后流入右下 |
| **核心** | 自我 · 幼苗 | **中央偏下**，扎根土地；**所有根脉由此长出**，是所有区域的视觉原点 |

> **三处禁用**：不使用透视网格线、不使用等距硬边块、不使用地砖——保持「中式田园 + 晨曦金」调性。2.5D 靠「尺度递减 + 色温递减 + 模糊递增 + 层次遮挡」实现，**不靠透视变换**。

### 7.2 根脉（替代直连线）

#### 7.2.1 视觉语义

**根脉 = 从「我」这株幼苗的地表根部，向各区域地下/地表延展出去的一束根须。**

- 它不是「数据连线」，也不是「管道」；它是**植物长出来的东西**——是「我」主动伸出去的部分。
- 因此**每一条根脉都从自我出发**（星形拓扑，根脉不横向互连，不画家人↔爱人）。
- 根脉**埋在地表附近**：靠近自我的一端在地表以下，越靠近目标区域越**抬起并露出地表**，最终**与目标区域的根部/地面相接**。
- 语义定调：**「我伸出去的根，够不够到、够不够牢」**——表达的是**我的投入与这段关系的承载**，而**不是对方的评价**，更不是分数。

#### 7.2.2 三档养分 → 根脉形态（沿用养分分量档位，不新增阈值）

| 档位（养分分量） | 根脉形态 | 可见度 | 附加 |
|---|---|---|---|
| **薄** | **一根极细的独根**，贴着地表几乎不露出 | 很淡 | 无流动；近似「将伸未伸」 |
| **中** | **一根主根 + 2 条小分叉**，显露出地表 | 中等 | 静态微光 |
| **厚** | **主根明显并分出 3–4 条侧根**，地表出现**细小的土壤隆起** | 明显 | **沿线缓慢流动的养分光点** + 端点极轻呼吸光晕 |

- **过渡**：档位切换**必须可见渐变过程**，不瞬切，让用户看到「它变粗了」。
- **首次出现某关系**：根脉由自我端**向外「生长」延伸到位**，随后有一次极轻的高亮脉冲。
- **长期无记录**：根脉降至「薄」并**保留不删**（不否定用户曾有的关系）。

#### 7.2.3 根脉与「只表达定性感受」的关系（宪法对齐）

| 维度 | 口径 |
|---|---|
| **内部数据** | 仍是该关系类别的**单一养分分量**（数据结构认知不变） |
| **视觉载体** | 原直连线**改名为「根脉」**（语义更准确）；路径仍从自我 → 目标区域，但**形态改为根须**（更粗的起始端、分叉、贴地行进） |
| **承载信息** | 只承载「**粗细 / 可见度 / 是否流动**」三种**定性**感受 |
| **绝不承载** | 不显示数字、不显示百分比、不支持 hover 出数值、不做「进度条化」 |
| **与形态的关系** | 根脉三档 与 区域三态 **同源同档**（同一个养分分量同时驱动），保证因果可读 |

> **一句话**：根脉只是**把原连接带换成更符合「花园」隐喻的形态**，它表达的仍然是「我在这段关系上伸出去多少」，**不是对方如何，也不是一个分数**。

### 7.3 关系标签浮层胶囊

- **形态**：挂在每个生命体上方（或斜上方）的**胶囊浮层**，半透明暖米底。
- **结构（两行）**：
  - 第 1 行：**内联 SVG 单色图标 + 关系名**（如「家人」）——**无 emoji**；
  - 第 2 行：**一句定性短语**（≤12 字）。
- **文案模板**（`{关系名} · {定性短语}`），定性短语**由「形态三态」驱动**，且**按区域各有措辞**（避免五区同句）：

| 区域 | 沉淀期 | 生长中 | 繁盛期 |
|---|---|---|---|
| 家人 | 根系还在土里，慢慢来 | 根扎得深了，有了支撑 | 根系深厚，也给了你荫蔽 |
| 爱人 | 两株还在试着靠近 | 藤蔓已经绕到了一起 | 彼此托着，开成了一处花 |
| 朋友 | 溪水很细，但一直在流 | 有些近了，有些还在路上 | 溪水能坐得下人了 |
| 孩子 | 刚破土，安静地长 | 抽了新叶，围栏合上了 | 自己会站稳一点了 |
| 同事 | 帐篷先收着，也挺好 | 有了火，也有了坐的地方 | 在那儿，也有人的温度 |

> （注意）参考图原文案「朋友 · 有些近，有些近」为**语义空转**，已修正为「有些近了，**有些还在路上**」（诚实表达部分亲近）。**全表零分数、零百分比。**

### 7.4 四季氛围

**结论：四季「不新增独立页」，做内嵌氛围层 + 一个可随时打开的「花园季节」轻浮层。**

**理由：**
1. **现有系统已按月份自动映射季节**，改独立页等于推翻已跑通的自动季节逻辑，并额外处理「独立页季节 ≠ 时间季节」的矛盾。
2. **独立页违反产品语义**：产品是「打开花园就看到我的关系」，不是「去季节页看进度」。四季若成独立页，会被读成**关卡/赛季**。
3. **信息密度不足撑一页**：四季的信息量 = 色温 + 文案 + 少量粒子，做成整屏页会显得空，反而催生「加进度条填充」的冲动。
4. **不阻断主路径**：用户主路径是「花园 → 点开浮层胶囊看得更清楚」，不应被季节页打断。

**落地规格：**

| 项 | 规格 |
|---|---|
| **主形态** | **内嵌氛围层**：季节 = 色温 + 光斑密度 + 状态文案，**永不显示数字/进度条** |
| **四季氛围参数** | 冬·沉淀季（雾蓝调，缓慢呼吸）/ 春·生长季（晨曦金，默认）/ 夏·繁盛季（暖橙，光点更快）/ 秋·收获季（偏金，偶尔飘叶） |
| **季节文案** | 冬「关系在安静地沉淀」/ 春「你的关系正在慢慢生长」/ 夏「关系正值繁盛」/ 秋「你收获了一些理解」 |
| **推进规则** | 当**所有存在关系**的生长阶段均领先于当前季节时，季节前进一档（最多到「秋」）。**无关系时不推进** |
| **入口** | 顶部季节状态处是一枚**可点击的文本按钮**（无图标、无箭头堆叠） |
| **展开形态** | **轻浮层（bottom sheet）**，约 40% 屏高，四行季节 |
| **浮层内容** | 每行 = 当前季节**定性描述一句**（如「土地在休息，根在往下走」） + `当前` 标记（**不是选中态、不可切换**） |
| **是否允许用户切换季节** | **不允许。** 四季由**当前月份 + 关系生长状态**共同决定，**不是用户可调设置**——否则会变成「主题皮肤」，失去叙事 |
| **参考图「冬春夏秋四选」** | **不采纳**（会引入「自由切换 → 皮肤化 → 游戏化」三重风险）；若未来确有需要，须先拍板「季节是否还是叙事」 |

### 7.5 首次进入的空状态与首次生长动效

**原则：不要一次给完整花园。首次进入是「冬季 · 尚未生长」的空白空间，只有一株很小的「我」。**

#### 7.5.1 空状态规格

| 项 | 规格 |
|---|---|
| 场景 | **冬季氛围**：雾蓝调、光更淡、光斑少、地面留大片留白 |
| 唯一生命体 | **自我 · 幼苗**——体量**比其他任何版本都更小**，居中央偏下 |
| 五个区域 | **全部不存在**（不是灰色占位、不是虚线轮廓）——画面里就只有一株幼苗与空空的土地，以及远景一座雾山 |
| 根脉 | **零条** |
| 文案 | 主句：「**这里还是一片空地。**」副句：「**说一段话，它会开始长。**」（引导去输入页，不催促、不打分） |
| 导航 | 底部导航正常可用；「+ 倾诉」主 CTA 唯一高亮 |
| 禁止 | 不得出现任何灰色占位圈、骨架屏、进度提示、`0/5 已完成`类文案 |

#### 7.5.2 首次生长动效节奏（第一次分析成功后，总时长约 3.4s）

| 时间 | 动作 | 动效细节 |
|---|---|---|
| 起始 | 场景**季节切换**（冬 → 当前真实季节） | 雾蓝 → 晨曦金，色温过渡 |
| 稍后 | 空地上**先落下一片土壤隆起** | 极轻的波纹扩散 |
| 继而 | **自我幼苗抽高一节** | 体量不变，**加一对叶** |
| 继而 | **第一条根脉从幼苗根部向目标区域「生长」延伸** | 由自我向外延伸 |
| 继而 | **目标区域的生命体「长出来」** | 淡入 + 轻微上浮；**不是弹跳、不是缩放放大** |
| 继而 | 该区域的**标签胶囊**淡入 | |
| 继而 | **一次极轻的全场暖光脉冲** | 表示「花园醒了」 |
| 结束 | 之后**不再重放** | 播放后写幂等标记（键名见架构文档） |

- **触发条件**：仅当关系账本从「全空」变为「有 ≥1 个关系有事件」时播放一次。
- **可跳过**：若用户此时已离开花园页，**不阻塞、不排队**，下次进入直接看终态。
- **不提供跳过按钮**（已定稿）；动效总时长**不得超过 3.4s**。
- **无障碍**：尊重 `prefers-reduced-motion: reduce` → 全部动效降为**直接切换终态**。

### 7.6 关系记忆光点（故事卡）

#### 7.6.1 触发与上限

| 项 | 规则 |
|---|---|

## 9. 三能量叙事（理解 / 修复 / 连接）

**结论：引入三分法，但只作为「来源标记」，不作为三套独立数值。全系统仍只有单一养分总量。**

### 9.1 为什么不做三套独立数值

| 代价 | 说明 |
|---|---|
| **宪法风险** | 三套独立数值必然被呈现为三个可比数字 → 直接踩 A2/A3/A4 的分数禁令；即便不显示数字，也极易被做成三条进度条 |
| **复杂度爆炸** | 会出现 **3 个独立阈值系统**；用户看不懂「理解够了但修复不够」时花园到底长不长 |
| **数据不足** | 单条记录的养分增量本就很小，拆成三份后**噪声远大于信号**，波动会显得随机 |
| **与「主轴 100/0」冲突** | 我们已裁定一次分析只给一个关系 100% 养分；再拆成三能量比例，等于**在错误的地方重新引入了「半亮」问题** |
| **对用户无增量价值** | 用户真正想知道的是「**这次我多懂了一点什么**」，而不是「我这次理解分涨了 1.7」 |

### 9.2 采纳方案：单一总量 + 来源标记

- **每条记录带一个「来源」标记**，三选一：`理解 / 修复 / 连接`。
- **来源标记不参与任何数值计算、不驱动任何视觉档位**，是**纯叙事元数据**。
- **判定来源**：优先取 AI 已返回的情绪/责任分布信号的**定性归因**（若可用）；否则**兜底规则**（确定性、可测）：

| 事件特征 | 标记为 |
|---|---|
| 以「倾听 / 说出真实感受 / 看清自己」为主 | 理解 |
| 以「争执后缓和 / 道歉 / 重新开始对话」为主 | 修复 |
| 以「久未联系后的重新靠近 / 主动发起」为主 | 连接 |
| 无法判定 | 理解（缺省，不新增第四类） |

### 9.3 三分法的唯一用途：差异化文案（不给数字）

| 用途 | 具体表现 |
|---|---|
| **故事卡** | 卡片上一枚**内联 SVG 小图标**（三种形状：镜 / 缝合线 / 连线）**仅作来源标识**，无数字、无百分比 |
| **成长建议的开场句** | 理解 → 「你已经看见了不少，接下来可以试着说出来」；修复 → 「有些裂痕已经开始愈合，可以先从小事说起」；连接 → 「你们重新连上了，接下来把它变成习惯」 |
| **顶部本期摘要** | 三条定性短句**轮播**（不做同屏三列对比），避免被读成三个并列指标 |

> **落地约束**：来源标记**不得**出现在任何排序、任何阈值判断、任何宽度计算里。它是**纯文案元数据**。

## 11. 数据与写入的产品语义契约

> 本章只写**产品语义**（用户可感知的行为约束）；函数归属、数据结构 schema、哈希/去重算法、键名等实现细节，见架构文档 D.10 / C.5。

### 11.1 写入行为的产品约束

| 约束 | 内容 |
|---|---|
| **成功才写** | 仅在分析**成功**后写入用户的关系账本**一次**；加载中、失败、切换视角**都不写** |
| **只写一次** | 同一段对话的养分不被重复叠加（去重） |
| **主轴唯一** | 一次分析的全部养分给**唯一主轴关系**，不拆分、不按比例（见 §6.4/§6.6） |
| **分量驱动** | 每段关系的养分有**独立分量**，连接的档位由**该关系自己的分量**驱动，而非全局总量 |
| **总量与分量解耦** | 顶部「关系养分总量」是全局总量（用于顶部卡片）；各关系分量为根脉档位唯一依据 |
| **去重窗口** | **24 小时内**重复分析同一段对话**不重复计分**，仅触发一次极轻的连接脉冲（让用户感到「我又看了一次」但养分不虚增）；**超过 24 小时**的相同对话视为**新的理解**，允许再次计分 |
| **隐私一致** | 去重只存**不可逆摘要**，**不存对话明文**，与产品隐私底线（不存储原始对话）一致 |
| **写入后联动** | 写入完成 → 受影响关系的连接按新档位平滑过渡；若该关系首次出现，连接以「淡入 + 生长」入场 |

### 11.2 本轮范围裁定（不做的事）

| 事项 | 裁定 | 理由 |
|---|---|---|
| 用户显式选择「这段对话是关于…」（P1） | **本轮不做** | 本轮聚焦「重构为关系图语义」，不做新 UI；保留接口空位，UI 缺位时自然回落后续判定，**行为正确**。后续若做，放**输入页**（与「已粘贴」同屏，降低认知负担），不放花园页（花园是「看关系」，不是「填表单」） |
| AI 结构化关系字段（P2） | **本轮不做** | 改 AI 管线属范围外、有回归风险；采「字段不存在则跳过」，不影响关键词路径。列入后续版本 backlog（字段**仅中性分类**，禁任何诊断/审判词） |
| 底部导航第 3 项 | **保留「记录」**，不采纳「洞察」 | 「洞察」带「我给你结论」的俯视感，与「看见自己」的产品气质相悖；「记录」更中性、更贴近用户自身动作，且与术语「情境回顾」语义连贯。**结论：导航四项 = 花园 / 记录 / 倾诉 / 我的（图标全部改内联 SVG，无 emoji）** |

## 12. 待确认与已裁定事项

> **（注意）2026 更新：以下 Q-V2-1 / Q-V2-2 / Q-V2-5 已由 team-lead 裁定采纳，转为「已定稿」；Q-V2-3 / Q-V2-4 已从「待办」升级为「已执行」。**

### 12.1 已定稿（team-lead 已裁定，不得再翻案）

**Q-V2-1｜「关系温度」→ 保留但四档定性。已定稿。**

- 四档词：`还很安静 / 有些暖意 / 正在靠近 / 温暖`
- **追加约束一（team-lead 提出，已写入）**：四档文案**不是数值区间的变相**。特别禁止「温暖 / 很温暖 / 非常温暖」这类**递进感过强的排序暗示**——那等于把分数换了个说法。四档必须是**四种不同的状态**，而不是**同一个形容词的四级程度**：

  | 档 | 文案 | 为什么它不是「程度递进」 |
  |---|---|---|
  | 一 | 还很安静 | **状态**：没什么动静 |
  | 二 | 有些暖意 | **状态**：有了一点温度 |
  | 三 | 正在靠近 | **状态+方向**：在往一起走 |
  | 四 | 温暖 | **状态**：已经是暖的 |

  > 注意三档是「靠近」（方向），不是「更暖」（程度）——这是本组文案的设计要点。

- **追加约束二（team-lead 提出，已写入）**：温度档位**不得驱动任何视觉档位**——**沿用「来源标记」的同款约束**：不参与任何阈值判断、不参与任何宽度/透明度计算、不出现在任何排序里。它**只驱动一句文案 + 一处色温**，是纯氛围元数据。
- 逻辑上：它与养分分量**不是同一个值**，不显示、不参与计算，与第 9 章的来源标记约束同源。

**Q-V2-2｜底部导航第 3 项 → 采纳「保留『记录』」，不采纳「洞察」。已定稿。**

- **理由（team-lead 裁定原文，写入此处以防下一轮再被提议）**：
  > 这是一款强调「**看见自己**」的产品，「洞察」带有「**我给你结论**」的**俯视感**，与产品气质相悖；「记录」更中性、更贴近**用户自身的动作**。
- 补充一致性：「记录」与现有术语「**情境回顾**」（用户回看自己的记录）语义连贯；「洞察」则贴近「**数据看板 / 分析结论**」，与术语禁止清单张力更大。
- **结论：导航四项 = 花园 / 记录 / 倾诉 / 我的（图标全部改内联 SVG，无 emoji）。**

**Q-V2-5｜首次生长动效 → 采纳「不提供跳过按钮」。已定稿。**

- 已确认随本裁定生效的两条约束：
  1. 动效总时长**不得超过 3.4s**（§7.5.2 已给逐帧时序表）；
  2. **必须有 `prefers-reduced-motion` 降级**（§7.5.2 已写：全部动效降为「直接切换终态」）。
- 追加：不提供跳过按钮的同时，**若用户中途离开花园页，不阻塞、不排队**。
