## 三、离上线的差距（按优先级排序）

### 🔴 P0 · 上线前必须解决

1. **代码没进版本库**
   - `git log` 最新提交还是 V1 单文件时代（`02f3de8`）；V2 的 `src/` 拆分、`nodes.js`、判定链、全部测试都是**未提交的工作树中间态**。
   - 风险：一次误操作 / 换机器 / 磁盘故障 = V2 全部工作丢失。
   - **动作**：立刻分阶段 commit（建议按 T01→T05 的粒度补提交，而不是一个大 commit）。

2. **后端 CORS 全开（替别人买单的隐患）**
   - `api/analyze.js:13` 仍是 `Access-Control-Allow-Origin: *`。这是一个**按调用量计费**的 DeepSeek API，任何网站都能直接调用它分析文本 → 等于你替陌生人买单，还可能被盗刷到欠费。
   - **动作**：上线前把 CORS 收紧为白名单（自己的域名），或至少校验 `Origin`。

### 🟠 P1 · 上线前应解决

3. **真实 API 端到端链路未验证**
   - E2E 目前只测了前端 DOM/交互，**没有测真实的 `/api/analyze` 调用**（粘贴对话 → 分析 → 落盘 → 花园生长的完整链路）。QA 方案里建议用固定 fixture JSON mock 掉 API。
   - **动作**：补一条「mock `/api/analyze` 的主链路 E2E」，确认 `report.js` 写入账本的链路真的通。

4. **合规三件套**（情感/人际关系敏感数据产品，中国上线尤其关键）
   - 隐私政策（收集什么、是否上传对话到第三方 AI、本地 localStorage 存了什么）
   - 用户协议（服务条款）
   - 若面向中国用户公开运营，还需确认：**生成式 AI / 算法备案**要求，以及「对话内容不落服务器」这一隐私亮点的明确表述（当前是纯 localStorage，这是卖点，要写清楚）。

5. **账户体系定位未决**
   - `space-screen / account-screen / login-screen` 目前是占位（「模拟对话」、账号页是导航占位）。
   - **需要拍板**：是「纯本地、无需注册」（隐私卖点，但换设备数据丢），还是「接真实账户 + 云端同步」（体验好，但引入账号体系和数据合规）。这决定了上线范围。

### 🟡 P2 · 打磨项

6. **产品人工验收**：PRD §13 的验收清单里，「美学调性」（暖金是否荧光、标签对比度是否够、动画呼吸感）机器判不了，需要 `qa-screenshots/` 截图 + 人眼确认（项目已有此模式）。
7. **文档同步 + 版本号**：README 状态、version 字段（现为 0.1.0）与真实进度对齐。
8. **回归**：`npm run check`（lint + test）作为提交/部署前的固定门禁。

## 五、关于「上线程度」的诚实判断

代码和工程已经**远不止「可用原型」**——分层清晰、测试充分、宪法守护到位，这些是很多「已上线」项目都不具备的。

卡住上线的**不是代码，而是「收口」**：没提交、后端留了个计费漏洞、真实链路没端到端跑过、合规文档没有。这四件事补上，它就是能上线的东西。
