# 小步迭代工作约定

## 核心原则

**不做一次性大改动。每个改动走完 "确认 → 执行 → 验证" 的完整小循环。**

## 工作流程

```
1. 你用大白话告诉我想要什么感觉 / 什么效果
   可以用截图 + 标注，也可以纯文字
   不需要任何专业术语
   ↓
2. 我输出「理解确认」：
   - 用大白话复述：我理解你想改什么
   - 用大白话说明：我打算怎么改
   - 不写代码，先说清楚理解
   ↓
3. 你看我的理解对不对
   不对 → 告诉我哪里理解错了，我重新理解
   对了 → 说"确认"或"对"
   ↓
4. 你确认后，我改一小块代码
   ↓
5. 你刷新浏览器，截图对比（改前 vs 改后）
   ↓
6. 不对 → 回到步骤 1 继续调
   对了 → 进入下一个改动
```

## 关于「理解确认」

- AI 必须先输出理解，得到确认后才能写代码
- 理解确认用大白话，不写技术术语
- 理解确认包含：想改哪个位置 / 当前什么效果 / 想要什么效果 / 我打算怎么改
- 用户可以否决、修正、补充

## 改动粒度

- 每次只改 **一个组件 / 一个区域 / 一个动画**
- 不要一次改 3 个文件
- 如果改动涉及多个区域，拆成多次对话

## 沟通方式

- **你可以用任何方式描述**：日常用语 / 感觉 / 比喻 / 截图标注
- **你不需要会任何专业术语**，CSS 属性、色值、像素这些是我的事
- 如果你说"感觉太冷了"，我会自己理解为色温偏蓝，改成偏暖的色值
- 如果你说"字看起来有点挤"，我会自己理解为间距不够，增加 padding/margin
- 我用大白话回复，但会在括号里标注对应的技术参数供你参考

## 验证方式

- 改前截一张图
- 改后截一张图
- 两张对比，确认效果

## 禁止事项

- ❌ 一次性描述 5 个改动
- ❌ AI 不经确认就直接写大量代码
- ❌ 不截图就说"不对"
- ❌ 一个改动没验证就跳到下一个
