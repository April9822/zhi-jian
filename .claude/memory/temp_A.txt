# A. 8项风险矩阵逐一评估

## R1: AI谄媚倾向（偏袒上传者）——🔴 高风险

**当前状态判断：设计层面充分，实现层面待验证。**

干预策略在三份核心文档中高度一致：(1) 双侧分析强制（即使只有单方输入，AI必须为缺席方构建「最佳解释」）；(2) 平衡检查 prompt（每个分析步骤末尾追加自检）；(3) 用户提示（报告开头标注分析基于单方输入）。这些措施在 HCI分析报告、产品说明、产品核心原则、AI分析管线规范中均有明确记录，设计层面对齐度很高。

**关键缺口**：所有约束都存在于 Prompt 层面，但 Prompt 约束不是代码级别的硬约束。DeepSeek 模型可能在长对话中「忘记」System Prompt中的双侧分析要求。当前没有任何输出侧的后处理检查机制来验证双侧平衡性——这需要在 AI工程师实现阶段补充一个「偏袒度检测」模块——例如，用独立的评分 Prompt 对主分析输出的双方评价数量/严厉程度做定量对比，若差值超过阈值则自动触发重新平衡。

**竞品血证**：澎湃新闻(2026)记录的29岁女性因男友长期用AI分析争吵、贴BPD标签而分手的案例，直接证明了R1放任不管的真实后果。这是所有竞品（情侣法庭、柯基小判官等）的共同缺陷，也是知间核心差异化机会——差异化必须在代码中兑现，而非仅在文档中承诺。

## R2: 人格标签化——🔴 高风险

**当前状态判断：文档层面已建立禁止体系，但存在内部文本自相矛盾——这是本次审查发现的最高优先级问题。**

知间宪法（product-principles.md）和 AI分析管线规范已建立硬性禁止词库，明确禁止「回避型人格/NPD/BPD/边缘型/自恋型/讨好型/控制型/依赖型」等术语。禁止词汇库在三个文档中重复出现，说明团队对此风险高度警觉。

**严重问题：产品说明文档（idea-vault/product-brief-argument-anatomist.md）的维度③「沟通风格初步识别」中，仍然列出了「回避型：沉默、不回应、离开对话 / 防御型：不断解释、反驳、不承认 / 控制型：打断、主导话题、下结论 / 讨好型：不断让步、不敢表达自己的需求 / 情绪化：音量升高、用词激烈、人身攻击」——这些标签正是禁止词汇库禁止的内容。虽然该维度下方有一行小字「⚠️ 这是行为模式分析，不是人格诊断」，但输出文本中使用「X型」格式本身就是在贴标签，与禁止词汇库直接冲突。**

这条免责声明在法律层面几乎无保护力——用户（或对方）看到「控制型」三个字时，不会去读免责声明。澎湃新闻报道中AI给用户贴BPD标签的案例证明：一旦标签被贴，伤害已经发生，事后说明「这不是诊断」无法消除伤害。

**修复要求（一票否决级）**：产品说明文档维度③的展示方式必须与知间宪法对齐。应将「X型」改为纯行为描述句式，例如：「在这次对话中，你倾向于保持沉默、不直接回应对方的提问」而非「你是回避型」。所有「型」字后缀必须从面向用户的分析输出中移除。

## R3: 三角化（AI替代直接沟通）——🔴高风险

**当前状态判断：设计充分，三线防御到位。但V2付费模型会瓦解第三道防线。**

三条干预线：(1) 每个报告的 CTA 永远指向直接沟通——「破冰生成器」按钮标注「去跟 TA 聊聊，AI 只是一个起点」；(2) 产品内明确边界说明；(3) V1 每天1次免费分析——防止用户每吵一句就来问AI。这一防线在V1免费策略下尤其有效，频率限制就是最好的三角化预防。

**前瞻风险**：V2 付费版如果提供「无限分析」，R3 的第三道防线（频率限制）将失效。需要在V2产品设计中预先规划替代机制——例如，即使付费也限制「同一对话主题」的分析次数，或引入「分析冷却期」（例如：同一段对话24小时内只能分析一次）。

**补充建议**：除了产品层面的约束，AI输出中应包含一句校准用语，例如：「这份分析的目的是帮你理清思路——真正的答案只能在你们两个人的对话里找到。」

## R4: 隐私恐惧——🟡中风险

**当前状态判断：V1.0策略方向正确，但「零存储」承诺的边界需要更精确的表述。**

V1.0 策略（不登录、不建数据库、不存储任何数据、「用完即走」）在心理层面和实质层面都是正确的。中国用户对AI隐私的信任度整体偏低（高>70%概率），零存储是获取用户信任的最低摩擦路径。

**隐蔽风险1——API供应链数据残留**：「分析完成后立即删除」这个承诺指的是「知间服务端不存储」，但用户的对话数据在传输过程中经过 DeepSeek API——DeepSeek 的 API 使用条款中是否包含数据留存条款？如果DeepSeek保留了API请求日志或用于训练，知间的「零存储」承诺在法律意义上是准确的（知间的服务器确实没存），但在用户感知层面却是误导性的。

**隐蔽风险2——Serverless 日志**：Vercel Serverless Function 的执行日志是否记录了请求体？如果Vercel的日志中包含了用户的对话内容，这也构成事实上的数据留存。

**建议**：(1) 必须核实DeepSeek API的数据留存政策，并在隐私说明中向用户透明披露「分析过程中对话文本会发送至DeepSeek进行AI处理，处理完成后知间服务端不保留，DeepSeek的数据处理受其隐私政策约束」；(2) Vercel Function需关闭请求体日志记录（通过环境变量配置）；(3) 在输入界面隐私承诺的下方用小字补充：「对话内容会加密传输至AI服务商进行分析，分析完成后知间不存储任何数据」。

## R5: 过度医疗化建议——🟡中风险

**当前状态判断：Prompt层面已设控制机制，但禁令存在内部逻辑冲突需要解决。**

干预策略清晰：仅在检测到明确的危险信号（家暴语言、自杀暗示、严重关系虐待）时才建议专业求助，且措辞为「如果你愿意，这里有一些可以帮助你的资源」而非「你需要看心理医生」。

**逻辑冲突**：禁止词汇库中包含了「看心理医生」「需要治疗」「心理疾病」「人格障碍」——这些词在正常分析中应当禁止（避免过度医疗化），但在检测到真正的危险信号（如自杀暗示、家暴语言）时，不引导用户寻求专业帮助可能构成伦理失责。当前的禁止词汇库是「一刀切」的，没有为危机场景预留例外通道。

**修复建议**：(1) 将禁止词汇库分为「无条件禁止」和「条件性禁止」两层；(2) 「看心理医生」「需要治疗」等词在正常情况下禁止，但在危机检测触发后允许使用；(3) 危机引导应导向具体的、有温度的资源列表（如心理援助热线号码），而非模糊的「建议看心理医生」。

## R6: 文化误读——🟡中风险

**当前状态判断：已识别问题并制定了部分对策，但执行深度取决于AI工程师的中文冲突词典质量。**

干预措施包括：(1) 中文冲突词典——覆盖中国特有表达模式（「随便」「你看着办」「呵呵」「我妈说」）；(2) 文化标注——分析涉及可能的文化因素时标注「中国文化中该行为可能有不同含义」。

中文冲突信号词典在AI分析管线规范和AI工程师定义中均有概要框架（8个条目），但条目数量远不足以覆盖中国冲突表达的丰富性：(1) 缺少地域差异——北方「直来直去」vs 南方「委婉含蓄」的表达风格差异；(2) 缺少代际差异——80后/90后/00后的冲突表达方式差异显著；(3) 缺少性别维度——中国社会对男女冲突行为的期待差异会影响AI的判断（例如女性表达愤怒更可能被AI判定为「情绪化」而男性则被判定为「有主见」——这是AI偏见的经典模式）。

**关键警告**：2026年7月15日微信情感类AI新规实施后，合规门槛提高。如果知间未来考虑小程序版本，文化的合规性审查将更加严格。

## R7: 破冰话术被误用——🟢低风险

**当前状态判断：设计已覆盖，风险可控。**

干预策略：提供3种不同风格（幽默/柔软/直接），让用户根据对方性格选择。产品说明中已纳入此设计。

**补充建议**：在用户选择破冰风格时，增加一行小字提示：「这段破冰话术的目的是开启对话，不是结束争论。选择一个对方最容易接受的方式。」——帮助用户在发送前做最后一步自我校准。

## R8: 服务质量不一致——🟢低风险

**当前状态判断：已制定输入质量检测机制，设计充分。**

干预策略：输入质量检测——对话太短（<5轮）或过于单方（一方发言>80%）时提示「分析可能不够准确」。QA测试员已定义了4个标准场景（包含边界测试——2句极短对话/单方发言>90%）。

**补充建议**：(1) 增加「中英混杂」场景的测试用例——中文互联网对话中英混用极为普遍（如「你这个project的deadline是什么时候」），当前测试规范未覆盖；(2) 增加「含大量表情/颜文字/emoji」场景——中文用户惯用「😂」「🥺」「[旺柴]」等，这些符号承载真实情绪，被OCR/预处理误删会导致分析失真。
