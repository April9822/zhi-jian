## 一、两个审查一致命中的阻断项（已修）

### 1. 「切换视角」会改坏原始数据（最严重）
- **问题**：报告页点「切换视角」时，`renderReport` 直接对 `analysis` 的数组 `.filter()` 回写，把另一方数据**永久截短**。第一次切到单人视角后，分享和「切回总览」都会缺数据。
- **修复**：`renderReport` 开头深拷贝一份 `view` 用于过滤渲染，原始 `analysis` 永远不动；`setupShare` 始终拿原始完整数据。（[src/main.js](src/main.js)）

### 2. 「关系能量」→「关系养分」（宪法红线）
- **问题**：核心术语规范里「关系能量」是禁用词，但残留了 5 处。
- **修复**：全部替换为「关系养分」。涉及 [src/main.js](src/main.js)（总分报告）和 [index.html](index.html)（空间页 2 处卡片 + 1 处正文）。

### 3. XSS（用户对话原句未转义 + 分享链接反射注入）
- **问题**：用户上传的对话原句（`said`/`text`/`original`/代表性原句）经 AI 回显时直接 `innerHTML`，可注入脚本；尤其 `?share=` 参数是**攻击者可控**的反射型 XSS。
- **修复**：所有 AI 输出 / 用户原句回显一律过 `escapeHtml()`，覆盖 `renderCoreInsight / renderResponsibilityRatio / renderDualColumns / renderReplay / renderWhatIf / renderEmotionAnalysis / renderEmotionRelief / renderIcebreakers / renderTotalReport / showRolePicker / renderSharedView`。

## 三、我刻意没做的（及原因）

### 代码级「禁止词硬拦截」扫描 —— 未加
审查建议在 `JSON.parse` 后加一段字符串扫描，命中 🔴 词就拒绝。**我没加**，原因是：分析会回显用户原句（如 `said`/`text`），而用户原句里出现「你错了」「你从来不」这类词极其常见（吵架记录本来就有）。naive 字符串扫描会把「引用用户原句」误判成「AI 自己说了禁止词」，导致几乎每次分析都被拒、产品不可用。

宪法里写的是「**Prompt 中硬编码拦截**」，不是代码级字符串拦截。所以本轮把完整禁止词汇清单写进 System Prompt，并明确「引用用户原始句子除外」——这才是符合宪法且不误伤的正确做法。若后续要上代码级拦截，需先让 AI 区分「AI 自己的话」与「引用原句」两个字段，再只扫前者。
