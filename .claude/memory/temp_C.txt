# C. V1.0「零存储」策略评价与V1.1+隐私建议

## V1.0 策略评价

### 优势
1. **对用户心理的精准洞察**：中国用户对AI隐私的信任度整体偏低，「不需要注册」比任何隐私政策都更能让用户放下戒备。这是以「不收集」替代「收集后保护」的正确思路。
2. **符合数据最小化原则（PIPL第6条）**：不收集、不存储是个人信息保护的最高境界——从根本上消除数据泄露风险。
3. **验证成本最低**：在品类天花板极低（全球竞品MAU<2,000）的前提下，零存储策略让V1.0可以以最低的合规成本和心理摩擦进行需求验证。
4. **与产品定位一致**：知间定位为「镜子」和「翻译」，而非「档案室」——零存储与这种定位一致。

### 风险与局限
1. **API供应链数据残留**（已在R4中详述）：零存储≠零传输。数据经过DeepSeek API和Vercel Serverless——这两个环节的数据处理政策决定用户隐私的实际边界。
2. **无法追责**：如果AI输出了有害内容（如劝分、贴标签），零存储意味着没有审计日志，无法查明具体是哪个请求出了问题，也无法为受害者提供证据。
3. **用户期望管理**：「不存储」容易被用户理解为「整个过程中没有任何地方留下数据」，但实际并非如此。这种理解差距构成潜在的信誉风险。
4. **产品迭代断层**：V1.0不存储任何数据意味着V1.0的使用数据（匿名统计如使用次数、场景分布、分析质量）也无法收集——团队在V1.0期间将「盲飞」，无法用数据指导V1.1的方向。

### 综合评分
- 隐私保护：⭐⭐⭐⭐⭐（在知间控制范围内）
- 用户信任：⭐⭐⭐⭐（不登录策略加分，透明度略有不足扣分）
- 风险暴露：⭐⭐⭐（供应链数据残留和用户期望管理是扣分项）
- 总体判断：✅ V1.0策略整体正确，但需补充两点：(1) 对DeepSeek数据政策的透明披露；(2) Vercel请求日志的关闭配置。

## V1.1+ 隐私建议

当V1.1引入注册登录和历史记录后，隐私架构从一个极简的「零状态」模型转变为一个需要精细设计的「有状态」模型。

### 建议1：分层存储架构

```
第0层 | 永不存储
  └─ 原始对话文本（对话截图、粘贴的聊天记录原文）

第1层 | 存储摘要（V1.1引入）
  ├─ 核心结论（100字以内的一句话总结）
  ├─ 行为模式观察（如「在3次分析中，你在冲突升级阶段倾向于保持沉默」）
  ├─ 沟通变化趋势（如「最近2次分析的倾听度较之前有所提升」）
  └─ 时间戳（用以生成趋势图表）

第2层 | 用户可控存储
  ├─ 用户主动保存的完整报告
  └─ 用户标注的「重要对话」标记
```

每一层都需要独立的删除控制。

### 建议2：端到端加密探索（V2+）

考虑在V2实现浏览器端加密：用户在本地输入后，前端先使用用户密钥加密对话文本，再将密文发送给AI服务——AI服务无法读取明文，分析结果在用户端解密。这条路径技术复杂度高，但它能使「零存储」从V1.0的「我们没有服务器」升级为V2的「连我们也看不到你的对话」。

### 建议3：自动过期策略
- 分析摘要默认保留6个月
- 6个月后自动匿名化（剥离用户身份，转入匿名趋势统计）
- 用户主动保存的报告不受此限制

### 建议4：数据可携带权（PIPL第45条）
- 用户可随时下载自己的完整数据档案（JSON格式）
- 用户可随时一键删除所有数据（含摘要+报告+模式分析）
- 删除操作需在前端展示明确的确认反馈（「已永久删除XX条记录」）

### 建议5：隐私仪表盘
在V1.1的个人页面中增加一个「隐私仪表盘」，可视化用户可以看到：
- 知间存了什么（具体字段列表，非模糊描述）
- 哪些数据会在什么时候自动过期
- 一键删除按钮

### 建议6：V1.0到V1.1的信任过渡
V1.0 用户在底部看到「想记住这次分析？[创建账号]」时，此处必须明确告知：
- 「创建账号后，我们会保存分析摘要（非原始对话）」
- 「你随时可以删除，我们说到做到」
- 不应以「保存你的分析」为默认勾选项来诱导注册——必须是用户主动选择的。
